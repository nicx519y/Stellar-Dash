# WebConfig 保存期间保留按键与灯效

普通自动保存不再使用停止按键监测、清除 LED 预览的独占边界。设备队列仍串行等待写入应答，Flash 提交、校验和 500 ms 写入间隔保持原有语义。校准、图片、升级、完成配置等显式操作继续使用独占边界。

STM32 的普通配置写入白名单允许常规按键监测同时运行；性能监测、导入和升级不在放行范围。WebHID 仅在普通配置处理器执行期间安装 QSPI 等待回调：每毫秒至多处理一次 RAM 中的按键状态、LED 动画和上报输出，不递归调用 RPC 分发，不渲染屏幕，不访问其他 QSPI 数据。作用域结束自动撤销回调，成功应答仍在保存和校验完成之后。

配置刷新保留按下状态、防抖历史和 ADC 采样；LED 亮度/颜色更新保留动画计时与涟漪状态。特效类型改变时只重置对应灯带的动画，主动关闭灯带仍正常关闭。

## 更新要求

需要同时更新 hosted WebConfig 与 STM32 application。旧固件仍会拒绝监测开启时的保存请求。采用现有 unlocked-development 构建/烧录流程；本次未烧录设备，也未修改保护位、锁定状态、Flash 布局或固件提交机制。

## 验证记录

- Web 类型检查通过；WebHID/Mock 回归通过；新增 provider 自动保存路径测试通过。
- 8 项原生测试通过，覆盖 QSPI busy/超时/失败及作用域恢复、反馈输出、亮度不重启动画、按键状态保留、配置写入策略与固定烧录文件校验。
- hosted 构建与产物隔离检查通过；application 使用 `HBOX_SECURE_BOOT_REQUIRED=0`、独立 `build_live_feedback` 目录编译链接通过。该目录用于编译验证，不替代既有发布包/地址校验流程。
- 扩大运行的 54 项旧固件契约测试仍有 4 项现有源码断言失败：LED 修复日志文本、校准页面卸载行为、重连弹窗代码定位、USB suspend 分支代码定位。本轮未改动这些断言对应行为。
- 本轮没有完成浏览器复测或实机时序验收。忙等待采用协作调度，不承诺硬实时零延迟；Flash 状态传输、校验以及当前 HID 命令仍有执行时间。

## 实机复测

1. Lighting 页面运行动态灯效，持续按住一个按键并调整亮度、颜色，跨越“正在保存”状态；灯带不应因保存全黑，动画应连续，松开按键应及时更新。
2. 保存过程中连续按下/释放按键，确认网页按键反馈以及按键触发灯效持续响应。
3. 切换特效及配置档，确认最终预览对应当前配置档；保存完成后重新连接读取配置验证持久化结果。
4. 校准、图片操作和完成配置仍应按既有独占流程执行；保存拒绝或断线不应误报成功。
