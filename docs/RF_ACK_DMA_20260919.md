# 2026-09-19 RF v3：ACK 时序与 TX DMA 复查

本轮由用户 10:55 左右的截图触发：8K 配置下有效接收约 5.8K，图表缺额约 27%。
这是调试版记录，不是稳定版本验收报告。

## 实测基线

RX RHD1 的 build ID 为 `0x1902`，确认运行 v2。对重复日志按帧类型、序号、原始内容去重后：

- 119.016 秒内建链计数从 244 增至 487（243 次）。
- 约 119 秒内 ACK 迟到增加 198、CRC 增加 61,261、软件输入队列丢弃增加 626。
- 有效接收约 5,851 包/秒。每秒约 5 个软件丢弃解释不了每秒约 2,000 包的缺额。
- 曾有两个 monitor 进程同时记录相同 HID 帧；已关闭本任务启动的旧实例，保留用户实例。

图表 Packet Loss 使用目标速率计算期望包数，包含未发送、控制面静默、空口损失等因素，
不能把整个百分比解释成 CRC 或环境干扰。频道质量决策仍使用 RF 入队前的序号统计。

## 本轮 TX 修改

1. 一个 ACK 请求之后立即监听，原 remaining_slots 字段用于预留静默时隙。
   8K 预留两个时隙（250us），4K/2K/1K 各一个（250/500/1000us）；
   RX v2 保持按接收时间戳加 remaining_slots 和 30us 调度，不需要改空口包长。
   避免原先三包 burst 中 TX busy 跨过时隙，而 RX 仍按连续 125us 推算 ACK 时间。
   保留 100ms 健康窗口、10ms 两次探测、500ms 无 ACK 兜底。
2. 建链中发送 watchdog 只清理射频事务，不再每 10ms 重新开始 20ms SYN 阶段。
   这样即使连续丢失发送回调，也能够进入监听阶段。
3. TX_IDLE 不作为 DMA 完成信号，不再提前清除当前事务 busy。
4. Timer DATA 使用两个独立且四字节对齐的 DMA 缓冲区。CPU 构包模板不再与正在发送的
   DMA 缓冲区共用，避免准备下一包时 memset/写入上一包。
5. 短 DATA 在实际两次启动之间保留空口时间保护。默认 2M/7 字节/4us sendTime 下为
   112us；若中断补发过早，丢弃该过时时隙，不消耗控制请求和边沿。
   只有不超过 64us 的剩余尾部允许在 ISR 内等待，通常被构包时间覆盖。
   完整控制包仍等待 TX_FINISH。1M 显式构建采用更长保护，不能假定支持 8K。
6. TX/RX 重型状态机每个 625us 系统 tick 最多执行一次，减少反复关中断。
   RX 输入队列、USB 和中立输入服务仍每次主循环执行。
7. 短包切换到完整控制包前保留 300us 排空间隔，避免前一短包迟到的 TX_FINISH
   被当作新控制包完成，提前打开 ACK 接收。主机测试覆盖排空期间不消耗 ACK 请求。
   实机加入排空间隔后，固定频道配置由 TX pending 变为两端 applied，
   计数窗口从反复重连恢复为 8000 次定时触发、约 7930 次发送启动尝试。

## TX/RX 分层诊断

ADC 没有新数据时，TX 使用上一份输入，125us RF 定时器不等待 ADC。
新增每秒一次的 TX 计数快照，复用原控制包长度，分别记录定时触发、启动尝试和跳过数。
RX v3（build ID 0x1903）通过 RHD1 第 2 页转发，同时报告入队前空口序号缺口及收到数。
窗口溢出或过旧时标记无效，不伪造 DATA 吞吐；RX v2 可以通信，但不能转发此诊断。
RX v3 同时修正重连耗时起点，以及重复 FINAL 延长首包等待的问题。

## 对照与边界

- 单请求 ACK 后短观察窗口的建链及 ACK 迟到计数停止增长。后续普通复位后的运行窗口
  也观察到实际协商跳频和恢复；仍不足以代替两小时及百次故障验收。
- 固定频道 10/22 各约 20 秒，有效速率约 6.35K/6.03K；频道 39 自动模式约 6.25K。
  换频道未消除主要缺额。
- 所有短包等待 TX_FINISH 的诊断构建，Connected 样本约 4,157 包/秒、39 个错误/秒。
  CRC 明显减少但达不到 8K，因此没有保留这种短包回调门控。
- 单独双缓冲的 Connected 窗口仍约 6.5K，继续加空口间隔保护。
- 32us 等待上限及 tick 合并版本，Connected 样本约 6,384 包/秒、20 个错误/秒。
  CRC 显著下降，但发送/接收总吞吐仍未达到 8K；不能将缺额归因于 ADC。
- 每次烧录末尾状态查询附近观察到 DATA 停止；普通 `reset run` 后恢复。此相关性
  不足以证明根因，测试窗口应避开烧录/调试附着。未修改任何已验收烧录脚本或布局。
- RX v2 的连接耗时在收到新 SYN、但尚未走 RX 超时恢复的情况下未重置起点，
  可饱和为 65535；不能用这些数值评估重连 P95。本轮未把它当作时钟回绕证据。

## 验证

行为测试增加了：控制包发送跨过名义时隙时 ACK 仍有静默窗口、SYN 回调连续丢失时
不重置握手阶段、TX_IDLE 不提前释放 DMA、模板改写不污染上一 DMA 缓冲、
补发过早时丢弃时隙及保护时钟回绕。保留此前的回调丢失、迟到/重复 ACK、
跳频事务、USB 背压及烧录契约测试。

固定配对和 8K 默认速率保持。RX 仍由用户自行烧录。
实际 TX 更新仅用 `python tools/hbox.py flash tx`，检查 IAP 首 4096 字节不变并确认
APPLIED/COMPLETE。未修改任何保护位或锁定状态。
