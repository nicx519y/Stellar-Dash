# XORA USB / RF 延迟口径（2026-09-27）

两种模式的 `USB` 列统一为端点提交（DMA 数据准备完成、ACK 发布前）至 USB IN 完成中断的设备本地耗时，不包括 Windows/XInput API 或游戏处理。时间戳仍包含固件捕获及中断响应误差，不等于纯总线传输时间。

- 有线 `USB wait` 是原 `CH wait`：CH585 接纳输入至端点提交，包含提交前处理和排队。
- RF `USB wait`：RX 报告准备好至端点提交，包含排队和端点装载；`USB` 为提交至完成。两段相加覆盖原 RF `USB` 的区间，各段微秒取整可能使合计相差 1 μs。
- 有线六阶段合计、RF 阶段合计的原有范围不变；RF 空口阶段仍是估算，拆分不表示实际延迟得到优化。

## 协议与兼容

RX 使用 RLT3，保持 32 字节 HID 报告。字节 11 高六位为修订号，低两位为页号 0/1/2；会话、行号、前后按键状态与 flags 保持原字段位置。每页从字节 16 起按小端 uint32 存放本地微秒值：

| 页 | 字段 |
|---|---|
| 0 | ADC、Logic、SPI wait、SPI |
| 1 | TX、RF 估算、RX、USB wait |
| 2 | USB；其余字节保留为零 |

只合并相同记录、修订、flags 和前后状态的分页。三页收齐且阶段有效才计算完整总和；缺页或无完成标志不补零。提交时间戳与队列报告身份在原有临界区内交接，完成后才发布两段耗时。相比 RLT2，每次完整修订增加一页诊断发送，实机开销尚未验收。

监视器继续解码 RLT2 并保留旧原始值和总和，但旧固件及旧历史记录的合并 USB 值不填入新的两列，显示需更新 RX。旧监视器不认识 RLT3，需要同时更新监视器。STM32、TX 及 RF 空口格式未改。
