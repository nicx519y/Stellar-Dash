# LED DMA 三阶段对照（2026-09-25）

这是定位第 20～22 个按键灯闪烁的临时诊断，不是已验收的修复。
`HBOX_LED_DMA_DIAGNOSTIC` 默认 `0`，仅诊断构建设为 `1`，并使用
`HBOX_SECURE_BOOT_REQUIRED=0`、`HBOX_AUTO_SLEEP_ENABLED=0`。
烧录仍通过根目录 AGENTS 中的完整开发构建和正常烧录流程。

## 第二轮：重复发送与保持显示

用户实测第一轮 A 基本不闪、B 很微弱、C 明显闪。此结果仅表明发送方式／间隔
相关，不能区分长间隔本身的影响和高频重发快速纠正错误。

第二轮设 `HBOX_LED_DMA_DIAGNOSTIC=2`，产物目录为
`.hbox/led-ab/hold-state/artifacts/`。第 4～22 个键始终绿色、亮度 32/255；
前 3 个键用持续颜色标记两个交替的 30 秒阶段：

- 蓝色：整条按键灯约每 33 ms 重发相同数据。
- 红色：只发送一次该图案，DMA 正常完成后不再重发；按键灯仍供电，数据保持低。

阶段转换不调用 Stop，不切断电源、不改变 GPIO 模式；氛围灯在两段中保持蓝色、
33 ms 发送。忽略切换后第一秒，记录第 20 个键是持续闪、稳定正常，还是稳定在错误
亮度／颜色。后者可能是最后一帧出错后一直保持，不能被记录成“完全正常”。

若红色阶段仍持续闪，说明无需主控继续提交按键帧也能复现，但仍未排除线路噪声、
供电、灯珠或其他灯路干扰。若红色阶段稳定、蓝色阶段闪，重点查重复接收及帧时序，
不能仅凭这项试验认定 MCU 指令错误或硬件损坏。

```powershell
python tools/hbox.py web local-flash-stm32 --simple-execute --state-dir .hbox/led-ab/hold-state
```

诊断产物单独保存在 `.hbox/led-ab/diagnostic-state/artifacts/`，沿用本机已有

```powershell
python tools/hbox.py web local-flash-stm32 --simple-execute --state-dir .hbox/led-ab/diagnostic-state
```

执行前核对该目录 manifest 的无锁模式、签名、哈希及 A 槽，确认对应 ELF 含
`WS2812B_DiagnosticReset` / `WS2812B_DiagnosticService`，并核对烧录事务中的实际镜像哈希。
这条命令仅选择已构建的诊断产物；不会开启编译开关或重新构建。

## 观察方式

从 LED 运行开始自动循环下列阶段；无需按键或修改网页配置。

| 阶段 | 开头 2 秒的标记 | 发送方式 |
| --- | --- | --- |
| A | 第 1 个键蓝色，其余绿色 | 不变整帧缓冲，循环 DMA 连续发送 |
| B | 前 2 个键蓝色，其余绿色 | 普通 DMA，完成后由主循环尽快重发 |
| C | 前 3 个键蓝色，其余绿色 | 普通 DMA，发送间隔至少 33 ms |

每段标记结束后，全体按键保持绿色 30 秒，再保持蓝色 10 秒，然后进入下一段。
三段共 126 秒，自动重复。忽略切换颜色或阶段的瞬间；记录每段稳定显示期间，
第 20 个键是否闪，以及第 21、22 个键是否突然变亮。建议观察两个循环。

所有段均使用相同的 32/255 驱动亮度（约 12.5%，低于按键的 25% 硬件上限）。
氛围灯固定蓝色、相同亮度，始终用普通 DMA、至少 33 ms 间隔发送，保持第二路负载一致。
输入采样与通信沿用原运行流程；测试不跟随按键、灯效或网页预览改变颜色，也不保存配置。
观察期间不要切换配置、进入校准或改变灯光开关。

## 实现与限制

- 入口位于 `Drivers/PWM-WS2812B/pwm-ws2812b-diagnostic.inc`，由 LED 主循环驱动。
- A 阶段 DMA 持续拥有发送缓冲；完成回调仅计数，不释放、编码或复制。
- B/C 阶段复用同一已编码缓冲，避免把反复编码开销混入对照；忙时不启动下一帧。
- 数据内容/阶段切换时先停止本路再改缓冲和模式；切换瞬间不作为闪烁结果。
- A 保留当前 PWM 参数、CCDS 配置、启动函数，专门比较循环与间歇传输，
  不等同于把旧驱动完整恢复。
- B 的实际帧率受主循环与中断延迟限制，不能把它标成已经测得的 1000 FPS。
- 发生启动/DMA 错误即停止诊断，不自动反复重试；显式重启运行流程才可恢复。
- 未采集波形。主机测试只验证状态机、缓冲所有权、内容一致、时序安排与失败处理。

## 结果解释

- A 稳定、B/C 闪：优先查普通 DMA 的重装/帧边界路径。
- A/B 稳定、C 闪：说明与长帧间隔相关；不能直接断言 30 FPS 不符合灯珠协议。
- 三段都闪：对照未把原因限定在普通 DMA；继续查共同发送路径和电气链路。
- 三段都稳定：固定图案或受控负载没有复现原问题，需恢复动态内容逐项加入变量。

上述结果都用于缩小范围，不直接证明硬件损坏或某一条指令就是根因。
