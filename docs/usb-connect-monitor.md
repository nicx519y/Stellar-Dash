# XORA USB XInput 监测

## 使用与测量边界

有线链路为 STM32 → SPI BoardLink → CH585 TX → USB XInput → PC。需要 STM32 Application、TX Application 和 connect-monitor 均实现 USB 监测协议。产品发布版本号不代表协议能力；STM32 对具备 telemetry/control 能力的 USB XInput 设备发送只读 BoardLink 监测查询，以有效的版本、会话、事务号和回执确认支持。旧固件仍可显示已有电源信息，但不提供实测 USB 完成率或完整按键延迟。

在 connect-monitor 选择 USB，打开 HID；需要按键延迟时再打开 Latency。统计周期沿用 100/250/500/1000 ms。只有一个连接来源时自动选择；USB/RF 同时接入时保持当前选择。页面和独立延迟窗口共用来源选择，USB 历史按设备和会话保存，RF 数据不会加入 USB 曲线或平均值。

- **实测 Hz**：相邻有效设备快照的 EP1 输入完成计数差 / 设备微秒时间差。首包、复位、异常或超过 2 秒无新统计显示不可用。有效窗口内没有完成报告才显示 0 Hz。
- **累计接收**：CH585 接纳的有效输入；**待发送覆盖**：已有待发送报告被后续状态替换的次数（也包括相同状态）。这两个计数与 USB 完成数分别展示。
- **按键延迟**：STM32 采样触发到对应 EP1 IN 完成的区间估计。总时间包括 SPI 接收与排队；不包括采样触发前的物理行程，也不包括 Windows/XInput API 或游戏处理。
- **分段**：ADC、逻辑、SPI 发送前等待、SPI 发送、CH585 接纳后等待、USB 在途。跨芯片接收与解析等待已包含在总延迟中，因此可见分段的和不等于总延迟。
- **不完整事件**：缺来源、被覆盖、发送失败、时钟不可用、USB 完成超时和分页缺失均保留原因，不填成零。重复状态不会重置首次边沿的时间。

## 协议与实现入口

权威定义是 [usb_monitor_protocol.h](../common/usb_monitor_protocol.h)。HID Input/Feature 仍为 32 字节，不改变 XInput 输入报告或 10 字节 BoardLink 输入格式。

| 消息 | 用途 |
|---|---|
| UMC1 | 独立 USB 能力查询、配置、续租和回执；事务相关，CRC16 校验 |
| UMS1 | 设备时间、会话、接收/完成/覆盖计数、有效档位、USB 速度及诊断溢出 |
| UME1 | 四页按键事件；会话、事件、修订号、前后状态一致才合并 |
| BoardLink 0x0A / 0x8B | 异步监测查询、校准与 STM32 稀疏事件来源；使用现有帧校验 |

UMC1 与现有 Windows 客户端 HBC1 按 magic 分发，监视器不会申请 Turbo presentation。RF CTL1 只发给识别为 RF 的接口；WebConfig HID 继续排除。租约 3 秒失效，主机每秒续期；配置一致时只续期，重连或租约失效重新应用。

STM32 每秒查询一次 TX 监测状态，异步记录 t1/t4；TX 回传 t2/t3。CH585-minus-STM32 偏移取 `[t3−t4, t2−t1]`，不假设双向等时。校准有效期 2 秒，区间额外包含相对漂移 1000 ppm 与捕获/取整余量；这些是诊断误差模型，并非经过仪器校准的绝对精度保证。

首次能力探测最多成功发送三次查询；明确回复该命令不支持时立即停止，且不将此诊断拒绝升级为输入链路故障。未回应的旧固件不会被持续探测；重新选择角色后允许重新探测。只有收到匹配且新鲜的查询回执，才会启用 STM32 来源记录。2026-09-29 发布身份改动曾使开发版本 `0.0.0` 被旧的 `>=2.2` 判断误拒绝；此路径现已与产品版本号解耦，已有支持 UMC1/UME1 的 TX 无需为此修复更新。

来源匹配限定在 20 ms 内，并检查原始输入序号及前后按键状态，短于 8K 下 8 位输入序号回绕周期。过晚或发送失败的来源不参与旧序号匹配。TX 保留 8 条事件，STM32 保留 8 条待发来源；溢出计数可见。后台有界发送统计、延迟分页和 MPW2；EP1 完成 ISR 记录计数/时间并有界补发下一份已准备的输入报告；诊断组包仍在主循环进行。

STM32 诊断状态放在已有 D2 `.DMA_Section`，由角色选择显式初始化，不依赖 NOLOAD 区自动清零；不供 DMA 直接访问。TX 高频计数和计时函数使用 `.highcode`。两颗 MCU 的时间戳不直接相减，32 位计数与时间差按无符号回绕处理。

## TX EP1 连续补发（2026-09-27）

### 依据与改动范围

修改前已有 monitor 日志的一段 10.828415 秒设备时间窗口中，接收增量 86360（7975.31 Hz）、完成增量 20419（1885.69 Hz）、覆盖增量 65940。这是旧固件运行记录，不能作为下面新实现的性能结果。RF 主面板的有效无线接收率与 USB 页的 EP1 完成率也不是同一测量点。

本轮只改 TX USB 模块及其热路径编译选项，不改 STM32、RX、RF 空口、SPI 时序、固定频道和 monitor UI。修改前后核对 RX、TX/APP、RF Common 共 66 个 C/H/INC/汇编源码 SHA-256，内容一致；未重建 RX，也未运行已暂停的自动回归或设备采样。

### 输入与诊断调度

- 原生 XInput 使用 4 项 FIFO，每项保存完整 20 字节报告、事件 ID 和接纳时间，共 112 字节。输入接纳后立即尝试提交；EP1 完成后先清 DONE、更新 toggle、释放旧 DMA 所有权，再直接补发下一项。主循环仍作兜底重试。
- 队列满时淘汰最旧待发项并累加覆盖计数。超过 2 ms 的待发输入标记超时；未挂载、暂停或 HBC1 切换期间拒绝提交的边沿标记发送失败。这些原因分开保留，超时和发送失败不伪装成覆盖计数。
- 事件 ID 随具体报告移交，队列持有的行不能被来源匹配回收；相同状态后续报告不重置边沿。真实 USB 输入完成才计数，HBC1 中立报告不会计入。取消 Turbo ARMING 后恢复原生队列，Turbo、WebHID 和其他手柄 profile 保留各自端点所有权。
- 总线/数据通路复位同步清空队列和在途关联，更新监测会话；EP0 STALL 不再错误重置监测会话。挂载、suspend、延迟处理中的 transport reset 都参与提交门控。
- 诊断发送与完整事件扫描最多每毫秒执行一次，接收和完成计数仍逐报告更新。时钟余数处理去掉两次除法，时钟除数在复位阶段初始化；边沿初始化明确使用 SRAM 内存函数，避免编译器生成 Flash `memset` 调用。

### 编译与静态检查

`make -C RF_PHY_Hop/TX -j4` 最终增量编译通过（约 2 秒，进程超时 600 秒）。FLASH 110240 B；RAM 128268 / 131072 B，链接统计余量 2804 B，BSS 对齐后到栈顶的间隔为 2800 B。较前一版本 RAM 增加 768 B；没有缩小现有缓冲区、改链接布局或改 RF 配置。该间隔不代表已验证栈峰值。

ELF 反汇编确认队列提交、完成处理、补发及监测输入/覆盖/完成函数位于 `.highcode`，EP1 完成以尾调用进入补发；检查了报告发布在 ACK 之前、旧 DONE 清除在新 ACK 之前。新增补发链使用 SRAM 复制函数；时钟首次初始化的 `GetSysClock` 在复位时执行。既有通用输入入口仍调用 Flash 中的 HBC1 输入接纳函数，不能声称整个 USB 输入链全在 SRAM，也尚无各阶段实测耗时占比。仅保留既有 RWX LOAD 段链接警告。

## 持续运行降到 1K 与控制失败的后续处理（2026-09-27）

用户报告 EP1 补发版短时达到 8K，随后变为 1K，控制状态 Failed、统计间断。已有日志中两轮 8K 设备句柄随后关闭，新的句柄以 1K 出现；新句柄的设备时间从不足一秒开始，而同一 boot 内监测复位不会清零单调时钟。这支持 TX 运行实例被重新初始化的判断，不支持仅凭曲线认定 EP1 硬件只能运行 1K。离线摘录保存在 `.hbox/usb-stability-existing-log-evidence.json`，没有启动新的设备采样。

STM32 现有恢复路径是：高速数据通路 FAULT → 尝试恢复兼容 SPI → 若恢复失败则请求 I09 → 重建 CH585 USB 角色一次并禁用本次快速输入，最终有效档位为 1K。该路径与日志现象吻合，但缺少本轮降档瞬间的 U06F/I09 与首次故障详情，尚不能判定具体是哪一种 SPI 故障。`Pending Overwrites` 是本会话内原生输入待发队列覆盖累计值，累加本身不会请求降档；不能用它代替 SPI 接收溢出计数。用户截图从 21 变成 2，需结合重启/清空记录理解。

本轮修正：

- 原生队列、监测时钟、统计快照及事件处理只屏蔽 USB2 中断，保留 SPI0/GPIO DMA/ready 中断响应；检查全部调用方后确认这些监测状态只由主循环与 USB ISR 访问。保留 SPI 模块本身的原子寄存器快照，不改 SPI 时序、优先级或故障保护。
- 原生输入只在 SRAM 更新 HBC1 有效档位；避免每份输入重复转换 XInput 按键、读取 Turbo 时钟并进入 Flash 中的 Turbo 提交函数。Turbo presentation 继续使用原有输入路径。
- `UsbMonitorPeer` 内部串行化整组 Feature SET/GET，覆盖设备发现配置与维护定时器的交错；使用请求自己的事务号，并丢弃已被新配置取代的状态结果。续租成功恢复 Applied，通信失败保留底层异常摘要便于定位。未改 RF 控制派发。

检查结果：TX 最终增量编译通过（约 2 秒），FLASH 110352 B、RAM 128372 / 131072 B，链接余量 2700 B；原有 RWX LOAD 警告保留。反汇编确认新的中断保存/恢复及档位更新函数在 SRAM，原生分支绕过 Turbo 提交；66 个 RF 源码哈希不变。monitor 类型检查通过（约 6 秒），Electron 构建通过（约 2 秒）。日志 `.hbox/usb-stability-{tx-final,typecheck,electron}.log`。

## USB/RF 共用电源轮询去阻塞（2026-09-27）

### 依据与适用范围

此前保存的 USB 记录表现为接近 8K 的平台、约 1 秒一次的小幅下凹，以及约 10 秒一次的更深下凹。源码中共享的 `PowerManager::loop()` 每秒同步读电源状态、每 10 秒额外核验充电配置；100 kHz 总线上的 7 次单字节与 4 次双字节读取，单纯线时约 4.32 ms，额外配置读取约 2.88 ms。这是源码与旧记录的关联依据，尚未通过新版对照确认全部下凹都来自这里。

USB 与 RF 都在 STM32 输入主循环中执行电源服务。RF TX 的独立定时器可继续发送缓存状态，无线接收计数维持接近 8K，不代表每份包都来自一次新的 STM32 输入处理。共用优化的预期收益是减少输入处理被电源事务推迟；RF 需同时查看输入新鲜度和按键延迟。

### 实现

- 电源 I2C 使用 HAL memory IT 传输，IRQ 优先级 7，低于输入/SPI IRQ；总线保持 100 kHz。固定持久缓冲由单笔事务拥有，主循环消费完成后才启动下一笔。错误或 20 ms 超时禁用、清除 IRQ 并复位外设，再允许复用缓冲。
- BQ25895/MAX17048 分步任务复用原有配置字段和解码函数。保留 BQ 故障锁存/当前双读、配置掩码、写后回读与整组核验，以及 MAX 告警清除和 EnVR/RCOMP 保留。故障、通信失败或核验失败关闭充电；中途新来的告警阻止旧快照重新启用充电。
- 每秒轮询、10 秒配置核验、5 秒离线重试都改为协作状态机。恢复时 ADC 等待以 20 ms 截止时间推进，最长仍为 1.2 秒；失败不退回同步初始化。普通轮询 500 ms、恢复轮询 2 秒总超时后废弃本轮，保持充电关闭。启动阶段同步初始化仍在输入运行前执行。
- STOP 入口增加软件事务所有权检查；休眠调度等整轮轮询完成，避免在两笔读取之间进入 STOP。未启用或恢复 Standby。
- TX USB SPI 应答结束后记录 W_INT 拉高时间，主循环到时解除下一次应答门控。保留普通/快速输入 1000 us、已确认快速 WebHID 20 us 的最短间隔，以及 NSS/DMA/ready 保护。移除该间隔的 DelayUs 等待，让外层解析和 USB 服务继续运行；RF SPI 通路未改。

- `make -C application HBOX_SECURE_BOOT_REQUIRED=0 BUILD_DIR=../.hbox/usb-monitor-stm32-build -j4` 最终通过，约 8.1 秒；`make -C RF_PHY_Hop/TX -j4` 通过，约 1.8 秒。每个构建有 600 秒真实超时。日志为 `.hbox/power-nonblocking-stm32-final-build.log`、`.hbox/power-nonblocking-tx-build.log`。
- STM32 AXI 静态末端 `0x2407dc9c`，余量 9060 B；D2 余量 95200 B。TX RAM 128388 / 131072 B，链接余量 2684 B。未调整布局或缩减缓冲；链接余量不代表栈峰值已验收。
- ELF 符号确认 STM32 I2C IRQ、HAL IT 传输、轮询状态机在 AXI RAM，TX 间隔检查在 SRAM `.highcode`。RF TX/APP、RX/APP、Common 的 66 个基线源码哈希一致；TX ELF 不含 BLE SNV 的 `Lib_Read_Flash` / `Lib_Write_Flash` 回调。保留已有未使用变量/函数及 RWX 告警，旧构建日志可核对相同告警。定向差异空白检查通过。
- 未运行暂停中的自动回归、设备采样、烧录或 RX 编译；monitor 没有本轮改动。摘要见 `.hbox/power-nonblocking-source-evidence.json`。STM32 编译输出仍是编译检查产物，不是完整签名/manifest 烧录包。

### 人工验收

需要更新 STM32 Application 和 TX Application；RX 不需更新。USB/RF 各自比较诊断关闭、只开统计、统计加延迟的持续运行窗口，重点看约 1 秒/10 秒下凹、USB 接收/完成/覆盖增量、RF 按键延迟，以及正常充电/电量更新；覆盖电源切换、离线恢复和正常休眠唤醒。尚无新版硬件吞吐、IRQ 耗时占比或监测开关对照结果，不能据编译通过认定波形下凹已消除。


## USB 延迟显示改为阶段合计（2026-09-27）

USB 表格最后一列改为“阶段合计”：直接相加 ADC、Logic、SPI wait、SPI、CH wait、USB 六项原始微秒值，以毫秒保留三位小数显示。缺少任意阶段或含非法数值时显示“阶段不完整”，不补零；右上角为最近最多 50 条阶段齐全记录的合计均值。主面板和独立窗口使用同一模型，RF 展示保持原有算法。

该数值不依赖跨芯片时钟偏移，也不使用旧 `Total range` 的上下界。它仅代表已测六阶段合计，不包括尚未独立计时的跨芯片交接间隙；页面明确标注这一范围。历史事件中的时钟估算字段保留，避免改变协议和原始日志含义。
