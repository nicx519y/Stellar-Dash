# RX v4 固定频道实测与下一步

当前设备确认 build ID 0x1904，固定频道 39，自动跳频关闭，TX/RX 配置均 applied。
本轮只读取数据和分析代码，没有修改或烧录固件。

## 60 秒观察

- RX 有效 DATA：454527 / 期望 482272，按固件窗口加权 7539.76 Hz，目标缺额 5.75%。
- 上轮 RX v3 基线约 6928 Hz / 13.40%；本轮增加约 612 Hz，缺额减少约 57%。测试不是同时进行，环境变化不能完全排除。
- TX 窗口均值：触发 8000.54/s、启动尝试 7919.71/s、跳过 80.82/s。
- RX 入队前序号缺口 365.31/s；CRC 43.88/s；软件原始包队列丢弃 131.57/s。
- 新短包路径提交约 7407.16/s。图表有效 DATA 在入队前计数，因此软件丢弃不会计入图表的 5.75%；不能把图表吞吐当最终输入处理/USB 吞吐。
- 重连、跳频、RX SetRx 失败、ACK fail/迟到/watchdog、已解码按键边沿 FIFO 丢弃，本窗口增量均为 0。
- 自启动累计最大值：接收重装 10us、接收分支 83us、输入提交临界区 34us、输入消费关键段 35us。它们不是本窗口平均/P95，不包括所有 IRQ mask 路径或进入回调前等待。
- 原始包队列丢弃可能发生在输入解码之前，后级边沿 FIFO 丢弃为 0 不能证明所有物理短按都被保留。

## 已确认的可削减工作

1. `demo_queue_input_payload` 仍然维护旧版 pending-input 单槽副本及奇偶 generation，每包复制 10 字节到 volatile 数组；当前消费者使用 32 项 FIFO，这份旧数组没有读取者。可删掉这个冗余路径，保留 FIFO、radio generation 与中立输入机制。
2. `demo_decode_short_input_payload` 仍然计算本机合成 payload 的 CRC。v4 已去掉后级对该 CRC 的重复验证，私有短包路径可进一步省去无消费者的 CRC 生成；保持外部旧格式 decode_v1 的 CRC 校验。
3. `demo_process_pending_input_payload` 仍全局关中断执行输入状态统计、延迟字段更新、按键到 XInput 的映射和报文复制。可改为短暂快照 FIFO，在开中断状态构包，提交时重新检查 generation/中立输入状态。必须覆盖构包期间重连、50ms 中立释放与 USB 失败重试，防止旧按键状态覆盖新的中立包。
4. 减少上述开销后，再用相同窗口看原始包队列丢弃与输入处理速率；仅扩大队列可能延迟溢出并增加输入延迟，不作为主要优化。
5. 接收重装 API 本窗口没有失败，最大软件重装耗时 10us，暂不优先调 IRQ 优先级或缩短 ACK/发送保护。TX started 仍只代表 SDK 调用尝试，若 RX 负载降低后序号缺口仍大，再补 TX 成功/失败分项及回调时序诊断。

下一版保持频道 39、8K、ACK 参数及 TX 不变，先清理冗余复制/CRC，再缩短输入构包临界区。吞吐收益与短按/释放行为都需要实测，不能只看接收包计数。
