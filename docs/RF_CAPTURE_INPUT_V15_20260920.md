# 测量开启时输入停更：TX v15

用户反馈 v14：关闭延迟测量按键正常，开启后按键不响应且没有延迟记录；
Report Rate 基本正常。该反馈说明收包率不能证明输入状态在更新，v14 未完成验收。
本轮仅分析代码、修改 TX 并编译；不采集设备、不运行回归、不烧录。

## 确认的代码耦合

`spi_rx_commit_latest_payload()` 原来在测量关闭时仅发布最新 SPI 输入快照。
测量开启后，每个有效 SPI 输入都会先在全局关中断区调用
`RF_SPI_FastWriteInput()`，执行 RF 输入更新、电池状态处理和链路时钟访问，
之后才发布同一个最新输入。RF 定时发送和主循环桥接还会各自消费该输入快照。
因此开启测量改变了输入处理的执行路径和临界区开销，而不是单纯记录时间。

NSS 上升沿中断原先还调用 `RF_SPI_InputComplete()`，在每个输入事务结束时
进入额外的 RF 记录更新及嵌套临界区。源记录存在本身不应成为输入发布的前提。

这些是静态代码可确认的耦合；当前没有证据将用户的完整停更唯一归因于其开销。
不能宣称已证明 CRC8 拒收了测量包：当前 STM32 的 CRC 生成和 TX 校验算法一致，
CRC 覆盖的输入包含测量 tag；本轮保留 CRC 校验，不以撤销校验恢复输入。

## 修改

- 开关测量统一使用同一个短临界区发布最新输入，SPI 解析器不再调用完整的
  `RF_SPI_FastWriteInput()`；RF 输入更新仍由已有发送/桥接消费者完成。
- 新增元数据专用 `RF_SPI_RecordInputEdge()`：仅事件 tag 变化时创建记录，
  不写 RF 输入状态、不处理电池、不访问链路时钟。与快照原子发布，保留首帧身份。
- NSS ISR 保留帧边界校验和时间戳缓存，不再直接更新 RF 记录。若解析先于 NSS，
  下一次 SPI 输入消费按原事件 tag/序号补齐边界；诊断发布前另有匹配查询兜底。
  不按键值猜测归属，不将缺失时间补零。
- 保留 v14 的 DMA 覆盖检测、不可变小块解析、CRC8 校验、有限测量扫描预算。
  RF 包长、正常发送频率、频道、固定配对、RX 和桌面端不变。

## 交付

`.hbox/rf-latency-v15-20260920/` 包含 TX.bin、TX_app.bin、构建日志、manifest 和
SHA256SUMS.txt。STM32 沿用 v13，RX 沿用 0x1913，monitor 无需更新。
这是待用户验证的修复候选，尚不能认定停更已消除。

更新使用原入口 `python tools/hbox.py flash tx`，使用仓库当前构建产物。
TX.bin 的现有 IAP 前缀不是授权从零地址手工覆盖 IAP；原流程仅更新 0x1000
以上 Application。本轮未修改烧录脚本、保护位或锁定状态。
