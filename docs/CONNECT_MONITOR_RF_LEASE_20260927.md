## 本次修改

- [HID source](../connect-monitor/electron/sources/hid-telemetry-source.ts) 将 USB TX 维护与 RX 控制分成独立串行队列；USB 设备的状态读取不再延迟 RF 续租。
- RF 续租独立每 500ms 调度，在当前控制操作结束后优先执行。忙时只保留一个续租任务，不再因为普通控制队列非空而直接跳过整次续租。
- 同一个 RX 上的原生调用仍串行。不会通过超时 Promise 假装取消驱动调用，也不会打开第二个 reader 或积压重复续租。
- 保留 RX 的 3 秒失效保护、原有静默恢复门槛和仅 RX 统计失效时的本地恢复分支。正常状态下不增加 GET_REPORT，不持续重发 RF 配置。
- 图表采样、缺口显示、频道配置和固件保持本任务修改前的行为；本任务未编辑工作区已有的固件和延迟协议改动。

## 诊断与验证

`runtime-diagnostics.jsonl` 的 `data.queues.hid.control` 新增：

- RF/USB 队列当前操作、排队时间及执行时长；
- 统计/延迟续租写入次数、失败次数、最后完成时间及耗时；USB 写入完成不等于固件确认；
- 最多 64 条近期控制异常、状态回执、续租定时器迟到、遥测缺口和重新配置原因。

诊断沿用 worker 状态消息及每 30 秒的异步日志，不额外读取设备。日志位于应用用户数据目录，仓库本地运行时通常为 `%APPDATA%/connect-monitor/runtime-diagnostics.jsonl`。

本次允许的验证是源码检查、TypeScript 类型检查和 Electron 编译。依照仍有效的暂停约束，不运行自动回归、设备采样或烧录。
完整退出并重新启动监视器后才会加载新主进程代码；实际断档是否消除须由用户验收。
若 RX 自身的原生控制调用卡住，优先队列无法抢占它；新诊断可区分主机排队/调用超时迹象与“续租写入及时但 RX 状态仍失效”，后者需要继续排查设备处理路径。
