# v18：撤回 v17 的中断调度改动

用户反馈 v17 再次出现开启延迟统计后没有反应。v16 是用户确认延迟已改善的
输入工作基线；v17 不能作为已验收版本。此次不增加新的调度优化。

## 定位范围与修复

相对 v16，v17 将 SPI0/GPIO_A 从默认抢占级改为与 TMR0 相同的 0x80，并将
DMA 游标快照的全局短锁改成只屏蔽两个外设中断。这改变了 NSS 输入发布和
SPI 回包 CNT_END 完成中断相对 RF 定时发送的服务时机，也改变了游标读取期间
允许的抢占。测量开启增加附带数据和事件处理，对此类调度改变更敏感。

回包完成前 TX 保持 pending/ready，STM32 输入入口检查到待取事件会暂停输入，
而 RF 定时器仍可能发送旧输入。因此“无线发送还在，按键状态不更新”不等同于
接收器断连。这是一条代码上存在的阻塞路径，但本轮没有实测确认具体发生的是
哪一条路径，也没有将优先级或局部锁单独认定为唯一根因。

v18 只撤回以上两项高风险调度变化：

- 显式设 SPI0/GPIO_A 抢占级为 0，恢复 v16 的默认优先级，TMR0 仍为 0x80。
- DMA epoch、DMA_END 和 DMA_NOW 恢复 v16 同一个短临界区读取及整体中断状态恢复。

保留 v16 的 NSS 快速输入、绝对字节位置判新、按实际 DMA 包关联发送尝试。
保留 v17 的 RAM CRC 表、已接纳旧输入免重复 CRC、电池处理移出发送 ISR、
短包不更新未使用的 watchdog 时钟及保护周期预计算。CRC 算法、包长、
保护时间、8K 速率、ACK 和频道策略均未改变。v18 不是完整回退到 v16 的二进制。
