# v22：定时换频与快速恢复实验

交付目录：`.hbox/rf-fast-v22-20260922/`。空口 v4，时序配置 2，RX build `0x1922`。需要匹配更新 TX、RX 和监视器；STM32 不更新。v21 文件保留在 `.hbox/rf-channel-v21-20260922/`，回退时双方一起回退。

本轮只做代码静态检查、编译及打包。**没有运行回归或离散事件测试，没有连接/采集设备，没有烧录。** 实验能力可由用户开启，所有硬件验收速率掩码仍为零。编译成功不能证明下面的时序目标达成。

## 1. 实现与边界

- `Common/include/rf_fast_engine.inc` 是 TX/RX 共用的生产状态机；离线程序直接编译同一文件，不复制另一套恢复逻辑。频道策略继续由独立 policy 模块负责，损失阈值不变。
- `rf_channel_radio_impl.inc` 是双方共用的 TMR2 执行器。TMR0 仍产生最新完整输入；TMR1 负责不可变发送保护、ACK 收发与绝对结束时间；TMR2 负责预约、排空、设置频道、建立保护、会合驻留和总期限。策略排序和报告在主循环。
- 提前预约的切换在边界前 300μs 禁止新的发送，排空已有操作，直到约定边界才设置频道。即时恢复切换从当前时刻开始排空。设置后保留 100μs 工程建立保护；首包单独使用 SDK `sendTime=120`（60μs）。返回旧频道走同一过程。
- 换频后的第一包是最新完整 DATA，不立即请求短 ACK，避免把首次发送保护挤入稳态 500μs 窗口。SDK 不带操作身份的 TX_FINISH 不决定连接态 ACK 的所有权；定时器、冻结 DMA、会话取消、频道、请求 token 及绝对期限共同控制有效性。
- 旧的备用快速恢复分支已移除。普通 PREPARE/CONFIRM/旧目标会合仍复用 manager/radio；快速恢复和普通切换互斥。
- 输入保持 5/7 字节。模式与恢复提交使用 12 字节事务，短 ACK 5 字节、扩展 ACK 12 字节。TX 实验状态/事件通过现有 7 字节附带通道延后传送，没有新增独立 RF 诊断发送时隙。
- 自动恢复备用频道是主频道索引 +1、+3，不代表实测最优。固定频道不会扫描备用。后台短测继续禁用。

## 2. 实验参数与时序依据

| 项目 | 配置 2 / 2M PHY / 4K、8K |
|---|---|
| 正常短 ACK | 20ms 周期，从请求实际启动起预约 500μs |
| 扩展 ACK | 单独预约 800μs，从请求实际启动起计算 |
| 默认关闭时的 ACK | 保留保守 100ms 周期及约 1750μs 接收窗口 |
| 同频道重试 | 原请求实际启动后 2ms |
| RX 失联判定 | 2ms 无合法 DATA，排除已预约维护静默 |
| RX 会合 | 主频道 2ms、A 4ms、B 4ms |
| TX 会合 | A、B 各 14ms，驻留包括切频成本 |
| 请求机会 | 恢复时每 1ms；ACK 预约期间不发输入 |
| 总期限 | TX 60ms / RX 80ms，重复请求不重新计时 |
| 换频准备 | 从排空开始至就绪最多 500μs |
| 迟到 | 定时动作迟到超过 125μs，退出快速流程并降级 |

800μs 扩展窗口的**工程模型**是：12B 请求保护 132μs + ACK 相对接收延迟 200μs + 首次长 ACK 保护最多 188μs + 调度余量 125μs + SDK/重启接收余量 155μs。普通短 ACK 不搭载配置；TX 每秒一次利用既有 ACK 机会发送 POLL，获得扩展控制。因此控制不被偷偷塞入 500μs 短窗口。启用协商自身在保守窗口完成。

有效监听检查要求最短 2ms 驻留扣除 500μs 准备和一个报告周期后，仍容纳完整 500μs 请求/ACK；14ms 覆盖完整 10ms RX 扫描周期、双方准备和请求相位。编译期参数适配仅支持 4K/8K，其他速率、非 2M PHY 不允许从 USB 启用。

这些是静态计算和实验初值，SDK 中部分无线过程为二进制库。`RFRole_SetParam` 返回成功不能证明 PLL 已稳定；100μs 建立保护也不是已测量的硬件上界。日志记录 Stop、SetParam、建立完成、SetRx 返回和首个输入，用户测试后才能调整参数。短 ACK 的可用余量较小；如果设备出现迟到/建立失败，应保持降级，不能通过删除保护规避。

## 3. 启停与恢复协议

USB 请求 → RX OFFER → TX SET → RX 确认 → TX ARM（固定生效边界）→ RX 确认 → 双方等待边界 → COMMIT_MODE/确认。界面复选框只表示请求，必须看到 TX/RX 两边实际启用。重复 ARM 不延长边界。协商不确定/超时走保守发现，不假定生效。

恢复时冻结原主频道、备用 A/B、会话、配置及速率。TX 原频道重试失败后尝试 A/B；RX 扫描收到合法恢复 DATA 时暂留，不提交主频道。TX 得到关联 ACK 后先发最新 DATA，再发 COMMIT_LINK；RX 验证原主频道、下一事务序号和已接收 DATA 后提交并确认。提交确认丢失允许同一事务重发，但不延长恢复期限。暂留后再次失去 DATA 时，RX 恢复冻结计划的扫描，不被单向 ACK 丢失钉在一个频道。两端最终受总期限约束并回发现。

实验开关不写持久配置。设备重新连接/重启后不会自动启用；时序故障会锁存降级，需要用户重新点击“重新启用实验”。监视器维持 USB 实验租约，断开后约 3 秒失效；RF 断开清理未执行注入。1K/2K 保持保守通信。一次开关请求不等于双方确认成功。

## 4. 烧录与运行

1. 保存当前工作，按原有普通无锁流程更新 TX 的 `TX_app.bin`（应用地址 `0x1000`）和 RX 的 `RX.hex`。不要将 TX 应用写到 `0x0000`。只需要这两个固件，不刷 STM32、IAP 或 ELF。
2. TX 日常入口仍是仓库原有 `python tools/hbox.py flash tx`，读取当前工作区构建产物。RX 由用户按原流程自行烧录。此文不改变工具、地址布局、保护位或锁定状态。
3. 关闭旧监视器，在 `connect-monitor` 目录运行 `npm start` 使用本次已编译的 `dist`。交付的 `connect-monitor-dist.zip` 是同一构建备份，依赖现有仓库的 Node/Electron 依赖，不是独立安装器。
4. 确认 RX build `0x1922`、RF 正常、4K/8K，进入 Channel debug 中的“快速恢复实验”。勾选开关，等待两边显示“已启用（实验）”。如果仅有请求、状态过期或降级，不能开始快速模式验收。
5. 备用恢复测试须在原有配置中开启自动频道。手动切频按钮会明确关闭自动并选择指定频道；测试后按需恢复自动。

包含 4K/8K 七频道有向切换、A/B/仅主/全部不可用相位扫描、ACK 与提交确认丢失、SDK 配置失败、定时迟到、单边重启、固定模式不漫游、旧提交拒绝、重复事务不延长期限、取消旧定时动作及低速保守模式断言。生产 TMR1 与 RF SDK 回调入口仍依赖硬件：宿主只模拟其收发契约，不把宿主结果当作这些中断的实机验收。完整发现握手终点也不由此模型代替。

**本轮没有执行上述断言**；程序已经编译交付，不存在“测试已全部通过”的结论。用户执行发现断言失败时，保留结果和 stderr，先定位逻辑问题，再做实机测试。

## 6. 实机测试入口与步骤

先固定速率、关闭延迟测量，记录开关关闭的基线；随后开启实验。每组都先“新统计区间”，不要沿用面板历史最大值作本轮结果。

### A. 单次换频

在当前频道稳定输入时，选择目标并点击“单次切频”；持续按/松键。记录切前最后一个有效输入到切后第一个有效输入的 RX 本地间隔。对 7×6 个有向组合分别测，4K/8K 各一组。一次调用 SetParam 的耗时不是切换输入间隔。

### B. 恢复和注入

| 选择 | 注入位置和含义 | 初次测试方式 |
|---|---|---|
| ACK 丢失 | RX 不发一次 ACK / TX 忽略一次 ACK | 验证原频道重试和提交 |
| DATA 丢失 | 仅 RX，拒绝有效 DATA 入口 | 持续 100ms |
| 确认丢失 | RX 拒绝确认/提交请求，或 TX 拒绝相应 ACK | 在相应事务开始前注入；未命中需重试 |
| 频道屏蔽 | 指定频道或全部频道接收入口逻辑丢弃 | 自动模式，主频道不可用，查看 A/B 恢复 |
| 仅指定频道可用 | 其他六频道逻辑丢弃 | 依次选主、A、B，验证备用覆盖 |
| 完成事件丢失 | 指定侧屏蔽 SDK TX_FINISH | 定时保护仍应完成发送，不因回调丢失卡死 |
| 启动失败 | 指定侧下一次 SDK 收发启动模拟失败 | 应锁存射频故障并回发现 |
| 定时迟到 | 指定侧 TMR2 入口注入超限迟到判定 | 验证故障分支；不代表真的阻塞 CPU 126μs |

ACK/确认/完成/启动/迟到默认注入一次且最长 100ms，DATA/频道按持续 100ms 注入。固件支持 1–255 次或 count=0 的纯限时模式，持续时间上限 5 秒（频道模式 4 秒），显式启动才生效。测试编号随命令发送，故障在生产入口处理，不直接将状态机改成“成功”。停止按钮取消后续批次并发出停止注入；在途事务仍由原截止期限收敛。

“100 次相位测试”把本地注入延迟在 10ms 周期内轮转，间隔 1.5 秒。TX 注入通过既有 ACK 下发，延迟从 TX 接到命令开始计算并向上对齐到 125μs；两侧不共享时钟，因此“双端注入”不是同步物理干扰。批次在双方状态过期/降级时停止，需要用户重新启用，不能自动绕过降级锁存。

仅 A 可用、仅 B 可用、仅主频道可用，选择“仅指定频道可用”并依次填写 Channel debug 显示的 A/B/主频道；全部不可用选择“频道屏蔽→全部屏蔽”。优先在 RX 注入；TX 的同类注入只屏蔽反向接收，属于单向丢失测试。真实射频不可通信另用遮挡/断电制造；软件屏蔽不等于抗干扰证明。

### C. 兼容与长期

- 4K/8K × 固定/自动 × 延迟测量关/开；输入始终使用最新完整状态，不重放历史键。
- 两种上电顺序、单边复位；确认没有永久分离，50ms 中立保护仍有效。
- 稳定场景两小时；每类故障累计至少 100 次。需要降级的用例每次由用户重新启用。
- 1K/2K 不启用实验；验证普通通信、配置和恢复未受影响。

## 7. 原始记录与统计口径

点击“导出 JSONL”。也可运行纯文件分析（不会连接设备）：

```powershell
python tools/rf_fast_tests/report.py path/to/rf-fast-experiment.jsonl --out result.json
```

RFD4 是双方支持/请求/实际状态、配置、事务序号、恢复成功/失败与事件溢出；RFE4 为本地事件。RX=role 0，TX=role 1。时间均为设备 uint32 单调微秒时钟，差值按同一设备取模计算。USB 到达时间只用于日志排序/区间选择，不冒充空口时间。

| 事件号 | 含义/统计 |
|---|---|
| 1 | 模式/恢复状态变更；value=状态编号，10 表示降级 |
| 2 | RX 检测恢复到首个恢复输入；不包含检测前等待 |
| 3/4 | 排空开始/保护结束，附预约时间与本地 generation |
| 5 | 事务 ACK；value=命令 |
| 6 | 切频后的首个输入；value=与切前最后输入的完整间隔 |
| 7 | 本侧恢复提交完成；不是首个输入时间 |
| 8/9/10 | 故障命中/注入启动/停止 |
| 11/13/14/17 | 射频配置组合调用、接收启动返回、SetParam、Stop |
| 15 | 本地逻辑故障开始到首个合法输入 |
| 16 | 本地逻辑故障解除到首个合法输入 |
| 19 | 各阶段窗口最大输入间隔：channel 字段此时为阶段 0正常/1ACK/2切频/3恢复/4建链，planned 字段为样本数 |
| 20 | TX 实际维护占用；value 为本观察区间微秒，at/planned 为区间端点 |

注入生效于“下一次匹配入口”，未命中不算已完成测试。若故障只在 TX 注入，RX 无法独立知道它的本地开始时间，不能制造一个 RX 的“故障开始→输入”数值；该项会缺测。要测这两个时间，使用 RX 本地逻辑注入事件 15/16，或另加物理观测手段。

固件事件环 64 槽，TX 通过 7B 分片传输，USB/附带通道拥塞可能缺记录；溢出显式计数。桌面原始记录最多 50,000 条，截断会标记。只报告已观测的成功、失败、缺测和 P50/P95/最大值；没有溢出标志也不等于证明日志完整。跨设备按测试编号/事务上下文关联，禁止时间戳直接相减。新 USB 区间重置 RX 本地统计；TX 摘要保留本机累计值，分析应使用本区间事件，不能把 TX 累计最大/计数当作区间值。

## 8. 验收判定

| 指标 | 目标 | 判定限制 |
|---|---|---|
| 正常切换有效输入间隔 | P95 ≤1ms | 用独立单次切频组的 RX 事件 6；恢复扫描不能混入 |
| 备用可用恢复 | P95 ≤40ms、最大 ≤60ms | 同时列出事件 15/16 与检测后事件 2；不能隐藏检测等待 |
| 稳定维护实际占用 | ≤3% | 事件 20 是观测区间；滑动 1 秒上界另由预约预算约束 |
| 发现重连 | P95 ≤500ms | 用现有建链诊断另测，不与恢复提交耗时混算 |
| 长期稳定 | 8K 两小时，无永久失联/卡键 | 由用户执行并保留日志 |

原有序号缺口、CRC、TX 未发送、软件合并继续分开记录。不能因输入缺额曲线下降就宣布验收。ACK 与扩展窗口均消耗维护预算；失联恢复单独作为故障阶段报告。预约仍有任意滑动秒保守预算，事件 20 仅用于实际占用观测，不证明所有滑动区间达标。

最终验收分软件逻辑、设备观测、物理边界三层。本轮全部实测结果为**未测量**，后台短测不开放，也不把实验开关或编译成功写成“已验收”。
