# v21：配置 ACK 和维护预算回归修复

用户反馈 v20 后接收率反复跌至约 4.7K–6K；截图 RF sequence gaps 为 2.23%，Input Deficit 峰值约 30%–40%。两个指标不同：前者是接收序号缺口，后者相对目标速率的输入缺额，包含 TX 未发送及恢复占用。不能把两者差异全部当作频道干扰。

## 确认的代码缺陷

### 配置 ACK 覆盖协议标记

RX `demo_fill_ack_packet()` 先在 `RFH_ACK_FLAGS` 写入 `RFH_SHORT_ACK_VERSION=0x80`，但配置分支随后在同一 byte 7（`RFH_ACK_MON_FLAGS`）赋值配置位 0x10/0x20，覆盖了格式标记。TX `demo_handle_ack_packet()` 对 12B ACK 先检查 0x80，因此在更新链路健康、应用固定/自动频道及测量配置之前就返回。

RX 每次连接后重新排入配置（最多 12 次），TX 连续三个 100ms 失败窗口或 500ms 无合法 ACK 会重连。两者结合可造成反复建链，增加 12B 控制包和输入空档。此错误确定存在；没有采集本次设备，不能断言每个图表尖峰均由它造成。

修复：RX 编码配置位时保留 0x80；TX 解析、保存及回执仅保留 AUTO_HOP/MEASUREMENT 配置位。合法链路 ACK 与配置处理的既有顺序保持不变，版本检查不放宽。

### 尚未获准的维护操作也暂停输入

TX 原先先等待 300us 控制包排空，再判断一秒 30ms 维护预算。预算用尽时仍保持待发事务并改发 DATA；新 DATA 又重启 300us 排空等待。8K 的 125us 节拍下，这条路径可能反复跳过两个输入时隙。

修复：新增预算可用性查询，先过期旧预约并检查额度，不扣费；只有可获准的控制包才触发长排空。预算不足继续普通 DATA，仍保留普通包 DMA 保护。通过保护后才实际扣除预算，等待排空的多个节拍不会重复收费。查询与扣费沿用 manager 调用方的串行化约束；恢复事务的既有特殊预算规则不变。

## 交付和边界

- TX/RX 编译完成，RX build ID `0x1921`，空口仍为 v3。更新两端；STM32 和 connect-monitor 沿用 v20 配套版本。
- `TX_app.bin` 为 0x1000 开始的应用；`TX_app.hex` 仅含应用地址范围；`RX.hex` 为接收器文件。
- 本轮仅代码分析、静态产物检查及编译。未运行回归、采集设备、启动监视器或烧录；尚未实机确认波动消失。
- 不改图表计算、不平滑尖峰、不降低 8K 频率、不缩短 DMA/切频保护、不新增无线诊断包。
- 后台短测、快速 ACK、备用频道快速恢复仍受原验收门控禁用；未扩大自动策略范围。
- 未修改 IAP、保护位、锁定状态或已验收烧录流程。

用户实机观察重点：先沿用固定频道，确认配置生效、连接不再循环；同时看 Report Rate、TX skipped/window 和 RF sequence gaps。稳定后再开启自动选频，避免把基础链路回归与频道差异混在一起。本轮不声明任何接收率/时延指标已达标。
