# RF 断连与重连失效分析、优化方案（2026-09-19）

本轮仅调查和制定方案，未修改或烧录运行固件。继续保留 TX/RX 固定配对地址
`0x6D35B8C9`、发现频道 `16/39`，无需恢复人工配对。

## 现场证据

时间为本机 UTC+8。来源为 connect-monitor 的原始 HID 日志，以及不暂停主控的
ST-LINK RAM 读取；原始摘录保存在 `.hbox/rf-drop-investigation/`。

| 03:47:56.651 | RX 进入 recovery scan，记录约 101 ms 输入静默 |

| 04:08:11.570 | 第二段连接开始 |

| 04:08:50.118 | RX 进入 recovery scan，静默约 101 ms |

两段 Connected 状态下的 RHM1 窗口，按接收包数/期望包数加权，表观损失约
14.9% / 15.4%。这包含协议停发、接收队列丢弃和空口损失，不能全部归因于无线干扰。
有效 RSSI 样本中位数均约 -37 dBm；信号强度不低，但不能据此排除干扰或接收时序问题。

RHI1 给出了直接的队列压力证据：

- 第一段约 128 秒：累计 pending drop 从 0 增至 18,385，采样队列占用中位数 11。
- 第二段约 38 秒：累计 pending drop 从 57 增至 5,848，增加 5,791，采样占用中位数 12。
- 环形队列深度 16、有效容量 15，两段都达到水位 15；这些丢弃事件可能包含正常包
  和 CRC 错误事件，不能全部算作有效 DATA 丢弃。
- 第二段结束前一个 RHI1 窗口：303 ms 内 348 个 CRC 错误、1,991 个合法 DATA。
  CRC 原因仍需独立验证。

连续约 10 秒读取 STM32 缓存的 TX STATUS：TX 一直返回 state=4 / connected=1，
ACK 成功、失败及发送失败计数均为 0。SPI 事务号和事件计数持续增加，因此不是
主控只显示过期状态。TX 这些统计每 5 秒清零，本次观察跨过多个统计周期。
主控输入采样、电源和 SPI 服务仍正常运行；RX 同时处于 Connecting。

## 已确认的代码缺陷及与现场的关系

### 1. 切频道可能遗留发送忙状态，当前发送模式缺少兜底

`TX/APP/RF_PHY.c:1391` 的 `demo_apply_channel()` 先 `RFRole_Stop()`，修改频道后
清除 ACK 接收/等待标志，但没有清除 `g_demo_tx_busy`。
TMR0 发送入口在 busy=1 时直接返回；如果停止射频中止了在途发送且没有后续完成
回调，发送会持续被阻塞。

`demo_check_tx_stuck()` 及主循环中的调用都受 `RF_AUTO_DEMO_TX_IN_ISR == 0`
限制，而当前编译使用 `RF_AUTO_DEMO_TX_IN_ISR=1`。ACK watchdog 又要求
`g_demo_ack_rx_active=1` 才工作，无法处理 busy=1、ack_rx=0 的状态。
连接健康目前依赖 ACK timeout 回调累积，缺少独立的“最后合法 ACK 时间”失联判定。

已从实际源码抽取切频道、试用回退函数及 TMR0 发送拦截条件，构建本地 C 复现程序。
模拟“控制包在途，Stop 后无 TX_FINISH 回调”，结果为：

```text
after probation rollback: channel=16 busy=1 ack_rx=0 wait_ack=0 RF_Stop=1 timer_blocks=1
```

设备对应旧 TX ELF 的反汇编也确认切频道函数没有清 busy。
这证明了代码存在可卡死路径；尚未直接读取 CH585 TX 的内部 busy 标志，因此
现场是否恰由这次中止回调缺失触发，属于与日志高度吻合、仍待新增诊断确认的判断。

### 2. 新频道试用失败时，TX 未协商就退回旧频道

`TX/APP/RF_PHY.c:1800` 的 `demo_link_quality_probation_failed()` 直接调用
`demo_apply_channel(old_channel)`，仍保留 COMM 状态，没有让 RX 同步回退的握手。
RX 留在新频道，100 ms 无 DATA 后开始扫描；若恰好同时触发上述忙标志卡死，
TX 不再发包也不产生 ACK timeout，RX 扫描再久也无法恢复。

两次永久断连都在切到 22 后约一秒出现，与试用期首个质量窗口失败的路径吻合。
此外，跳频恢复总超时后也直接回旧频道/COMM，应统一改为有明确结果的恢复出口。

### 3. RX 排队延迟进入了 ACK 的实际发送时间

`RX/APP/RF_PHY.c:1908` 的 `demo_schedule_ack()` 在主循环处理到请求时才设置
`remaining_slots * slot_time + 30 us` 相对定时，没有扣除从 `pending->rx_tmr`
到处理时刻的排队时间。TX 普通 ACK 监听窗口只有 1,200 us。

队列拥塞已由遥测确认。RHL2 的 `rxIrqUs` 实际是 RF 回调到主循环处理之间的时间，
日志可见约 0.8–1.4 ms，并非纯粹的硬件中断响应时间。相同队列中的 ACK 请求也可能
被延后，造成 ACK 迟到及重复重连；本轮未直接测到 ACK 空口时刻，需补诊断验证。
CRC 错误事件和正常包共用队列，也会增加压力并挤掉控制请求。

## 实施顺序

### P0：先消除“断了永远连不上”

1. 统一射频中止/重配置入口：暂停发送调度，在有界临界区协调 ISR 与主循环，
   Stop 后清理 busy、wait_ack、ack_rx、过期 burst 和事务状态，再恢复调度。
   覆盖切频道、试用回退、重连、Off/On；不能只在任意位置强行清 busy。
2. ISR 发送模式也记录发送起始时间并执行 watchdog。先以现有 10 ms 阈值为起点，
   区分发送在途和合法 ACK 接收窗口，验证无误触发后再缩短。
3. 增加最后合法 ACK 时间判定：初始建议连续 500 ms 无合法 ACK 即退出 Connected，
   停止当前事务并重新开始 SYN/ACK/FINAL。该机制不依赖 timeout 回调是否到达。
4. 保留 RX 的 50 ms 中立输入保护与 100 ms 失联检测，不靠延长超时隐藏断流。

### P1：让跳频及回退双方一致

1. 试用失败时通过已有 PREPARE/CONFIRM 流程协商回旧频道，使用新事务序号。
   若当前频道已不能通信，进入有截止时间的双频道恢复，最终退到共同发现频道重连。
2. 跳频失败、试用回退、重连成功分别记录原因；冷却及隔离期限不能被普通重连入口
   无条件清空，避免差频道之间反复切换。先修状态机，再评估是否需要调整阈值。
3. 所有恢复阶段必须有时间上限和统一出口；只有收到新的有效对端证据才能重新报告
   Connected。保留固定 bond，不跳过连接握手。

### P2：处理 8K 下的拥塞和 ACK 时序

1. 将 ACK 请求识别与截止时间计算放到短而有界的快速路径，按 RF 接收时间戳计算
   绝对发送时刻；同一 token 只发一次。已错过窗口的 ACK 记录为 late，不晚发干扰
   下一批 DATA。控制事务处理要保证在截止时间前完成，不能只给现有慢路径换个计时公式。
2. CRC 错误改为按频道聚合计数，控制包有独立容量/优先处理通道；正常输入保留必要
   按键边沿，避免简单只留最新状态吞掉短按。缩短每包解码/计时换算/USB 提交的开销。
3. 队列扩大只用于吸收短突发，不能替代吞吐优化；分别报告原始接收、CRC、队列丢弃、
   协议有意停发、ACK 迟到和 USB 等待时间。
4. 比较 4K/8K、固定工作频道/自动跳频、HID 遥测开/关；固定工作频道测试应通过两端
   一致的启动配置进行，避免引入当前 RX 手动固定频道分支的重配置后漏重挂接收问题。
   对 CRC 错误单独做距离/频道/USB 活动对照，不先盲调发射功率。

## 验收与可观测性

- 新增低频二进制诊断：TX busy/ACK 状态、最后进展与合法 ACK 的年龄、恢复原因、
  watchdog 次数；RX 队列水位/丢弃增量、ACK late、握手阶段、实际频道。
- 故障注入覆盖：发送中切频道、丢 TX_FINISH、丢 ACK 回调、试用失败、队列突发、
  RX 拔插，以及两种上电顺序；避免只测试正常重连。
- 初步验收目标：100 次故障/重连循环无永久卡死；对端恢复后在干净环境下 2 秒内
  重连；稳定连续运行 30 分钟，不出现 TX 长期 Connected 而 RX 无 DATA。
- 8K 下队列丢弃应消除，ACK 不再超期发送；在控制时隙扣除后单独评估真实空口损失，
  再确定最终丢包率目标。以上为待验证目标，不是本轮已达到的结果。
- 本轮不改已验收烧录流程，不修改保护位或锁定状态，不启用深度 Standby。
