# XORA 映射与灯效资源

## 开发与发布

源文件保存在 `resources/xora/*.xora-resource.json`。同一份源文件生成服务器运行文件和固件出厂资源；不要直接编辑生成的二进制或 `common/xora_factory_resources.hpp`。

```powershell
node tools/compile_xora_resources.cjs
node tools/compile_xora_resources.cjs resources/examples/pulse-scan.xora-resource.json .hbox/pulse-scan.xora-resource
```

第一条重新生成出厂资源，第二条编译独立资源。编译不访问设备或发布服务器。示例将呼吸、扫描和按住覆盖组合在一起，使用既有引擎能力。

在 admin 的“资源管理”上传 JSON 或运行文件，检查预览、兼容性、摘要，然后显式发布。灯效同 ID 的修订号必须递增，上传不能覆盖已有修订。改名、说明和封面属于目录展示信息；更改设备上的名称或效果需要新修订。运行文件不含说明和封面，重新导入时只能恢复设备运行所需内容。

WebConfig 的 Buttons Performance 暂不开放轴体映射更换入口，不展示映射资源卡片；后台资源管理和设备安装能力保留。Lighting Setting 分别提供按键、氛围资源的下载和应用。下载先存入设备，应用再更新当前 Profile；其他 Profile 保留各自修订。被引用的资源和出厂恢复资源不能移除。下架只禁止服务器新下载，已安装资源仍可离线运行。

Lighting Setting 沿用原有图标卡片，合并设备库存与服务器已发布修订。已安装卡片点击应用到当前 Profile；Outline 卡片点击仅作网页预览。悬浮或键盘聚焦满 0.5 秒显示带图标的安装/卸载操作，两类选择器共用单一悬浮状态，按钮向上渐入、向下渐出，触屏长按提供同等入口；安装成功不自动应用。右侧不再提供资源抽屉、当前资源名称行或骨架屏；每类先留一行空白，按 112 × 76px 卡片和 8px 间距计算行数，先以 240ms 动画撑高再显示列表。选择只更新引用，不重新拉取目录。按键灯和氛围灯统一在左侧 Hitbox 预览。氛围灯将公共引擎输出平滑映射到原始坐标中 10px 厚的连续外框，边框厚度随 Hitbox 整体等比例缩放，不绘制逐颗灯珠；保留独立颜色、速度、亮度、按键触发与同步模式，按键灯关闭时独立氛围灯仍可预览。灯光页复用其他主设置页的 228px Profile 侧栏、Hitbox 容器、缩放与居中规则，不再单独调整布局；氛围灯画布作为覆盖层，不参与布局尺寸计算。

Switch Marking 的空白和采样中的曲线保持管理员草稿。已有目录、修订 ID 和关联沿用原来的 SQLite 表，新旧目录接口访问同一份数据。后台重启不再自动发布草稿；完整性检查也作用于旧发布接口。旧数据库中不完整的已发布曲线不会出现在普通用户目录。

轴体兼容旧设备的映射身份：每个曲线修订使用独立的 `resourceId`，同一目录按递增 `revision` 关联历史。上传会保留文件的 ID、修订及运行字节；修订已有轴体时先在后台选择该目录，并为源文件填写新的 ID 和更高修订号。灯效保持同一 ID 递增修订。网页通过目录历史识别旧轴体的更新。

## 文件契约

唯一实现入口是 `common/xora-resource-codec.cjs` 和 `common/xora_light_engine.hpp`。多字节整数、IEEE-754 单精度浮点均为小端；不序列化 C++ 对象内存。

公共头固定 64 字节：

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 4 | ASCII `XRES` |
| 4 | 2 | 格式版本 1 |
| 6 | 1 | 类型：1 曲线、2 按键、3 氛围 |
| 7 | 1 | 引擎版本 1 |
| 8 | 4 | 非零修订号 |
| 12 | 2 | 负载长度 |
| 14 | 1 | ID 长度，1–15 |
| 15 | 1 | 保留，必须为 0 |
| 16 | 16 | ASCII 字母、数字、`_`、`-` ID，零填充 |
| 32 | 32 | SHA-256：头部前 32 字节连接完整负载 |

JSON 的硬件条件为 `hardwareVersion: "2.0.0"`，当前运行 ABI 对应固定的 22 键、40 氛围灯拓扑。未知格式或引擎版本拒绝加载。运行文件最大 2048 字节。

曲线负载为现有 220 字节 `HBOX-ADC-MAP-V1` 规范编码，包括 ID、设备名称、点数、步长、噪声、频率及最多 40 个原始采样点；不含逐键校准。曲线运行文件总长 284 字节。网页验证整个文件后，以其确切修订转换成原共享安装接口的参数和摘要，回读确认后提示重新校准。

灯效负载前 96 字节：三个 RGB24 颜色（各占 uint32）、层数（偏移 12）、时钟编号（13）、UTF-8 名称长度（14）、零保留（15）、80 字节零填充名称区（名称最多 79 字节）。之后为 1–8 个 32 字节图层：信号、起止颜色索引、混合、遮罩各 1 字节，3 字节零保留和 6 个 float32 参数。

信号包括 constant、sine、scan、radial、random-set、scan-latch、ring-tail、center-wave、pressed、triangle、envelope。混合包括 replace、add、max；遮罩 0 为全体，1 为按住的按键，2 为未按住。颜色索引 0–2 指向 Profile 的个人颜色；按键颜色顺序为按下色、背景色 1、背景色 2。氛围颜色独立保存。

图层参数前两项为相位倍率和空间宽度，必须为正；第三项供扫描位移倍率使用。现有资源剩余参数填 0。每个参数须有限且绝对值不超过 10000。时钟包括 10 秒按键周期（速度 1–5 倍）、`600*(7-speed)` 毫秒氛围周期和半长周期。多次按下最多保留 5 个活动涟漪。按键同步时范围包含全部灯珠；氛围独立时使用环带范围。单次播放结束回到底色。

设备只在选择资源时解析二进制；逐帧使用 RAM 中的图层和状态，不解析 JSON、不访问 Flash、不分配堆。亮度上限、30 FPS、开机渐亮、LED 电源和驱动仍由原硬件层负责。浏览器引擎与固件使用同样的确定性随机种子。

## 存储与配置

公共布局常量在 `common/firmware_metadata.h/.py`。ADC 公共区的前 12 KiB 保留原校准和共享映射；资源 A/B 库分别从 `0x3000`、`0x9000` 起，各 24 KiB，4 KiB 索引/提交区加 20 KiB 数据区，物理索引最多 32 个修订；产品安装限制为按键灯效、氛围灯效各 8 个修订（含出厂和保底静态资源），同时受 20 KiB 字节容量约束。已有超额库存不自动删除，但不能继续新增。其余固件、图片和 CH585 区域不移动。

安装重建非活动库，擦除限定区域、写入正文、逐页回读，最后使用不擦除的 `WritePage` 单独提交。资源 SHA 与整库 CRC 校验均通过才选择该库。加载读失败不作为空库处理；损坏库使用可校验的另一库，出厂资源也保留在固件中用于恢复；只有两类 revision 1 静态资源始终作为保底可用，其他出厂资源卸载后不再隐式加入库存或被运行加载。无法确认资源库存时报告 `storageReady: false`，拒绝新写入。

配置版本升为 `0x23`，每个 Profile 的两条资源引用附加在旧 Config 尾部。日志识别旧前缀长度和新长度；迁移用旧枚举填充出厂修订，保留颜色、亮度、速度、启用、同步和其他原配置。导出包含引用；导入要求对应修订已经安装，缺失时明确拒绝。资源文件独立导出和安装，不塞进配置 JSON。

回退到旧固件前，必须保留升级前由旧固件导出的兼容配置备份。旧固件不能解释新大小的 Config；回退后通过旧版导入流程恢复升级前备份。不要把新配置或自定义资源引用交给旧固件解释。本次没有改变冻结的烧录与升级流程。

## 接口

后台资源类型使用 Chakra UI outline Tabs 切换。灯效详情直接复用 WebConfig 的 Hitbox 绘制组件，保持机身、按键和氛围灯边框的缩放比例，氛围灯显示为连续外框；后台预览不依赖设备连接。当前 WebConfig 灯效选择器使用图标，因此后台只为轴体映射显示封面上传，灯效不要求封面；已有灯效图片数据仍保留。

管理员：`/api/admin/resources`，支持列表、上传、元信息和图片维护、指定修订发布、下架、源文件和运行文件导出。普通目录：`/api/resources`，支持列表、指定修订详情、`/source` 和 `/download`。管理员沿用账户和来源检查，普通读取沿用设备直连访问上下文。

设备 RPC：`resources_list/status/get`、`resources_begin/chunk/commit/abort`、`resources_apply/remove`。分块最大 256 字节；重传必须与已有数据相同。安装结果包含 ID、修订和摘要；网页另做完整回读。状态包含库容量、已用字节、Profile 引用和当前引擎加载引用。网页使用现有会话、队列和独占配置事务；安装与应用分别确认。库存增加 `limits`、`counts` 和 `removeWithFallback` 能力；缺少新能力时网页禁用安装/卸载并提示更新固件。安装拒绝分别使用 `RESOURCE_COUNT_LIMIT` 和 `RESOURCE_STORAGE_FULL`。

卸载请求显式传 `resetReferences: true`，先一次保存所有受影响 Profile 的静态回退引用，再刷新运行时并提交资源库删除。静态保底资源不可删除。响应报告 `affectedProfiles`、`fallback`、`configurationSaved`、`removed`、`runtimeReloaded` 及可选 `errorCode`；`removed: false` 不能视作成功。保存失败恢复 RAM 引用并保留资源；删除失败保留已保存的回退引用，允许重试。屏幕和快捷键仅遍历设备实际库存及静态保底资源。
