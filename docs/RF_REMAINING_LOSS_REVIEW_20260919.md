# 2026-09-19 固定频道余下缺额复查

本轮仅采样、阅读当前代码及恢复监控配置，没有修改或烧录固件。
发现 Electron 与 connect-monitor 两个 userData 的 monitor 同时运行，其中后者保存 autoHopEnabled=true；采样初段实际出现 39/34/10 三个频道。已备份日志、关闭旧实例，两套保存配置均改为固定 39，并仅保留常规 npm start 对应实例。最终 CTL1 flags=1，TX/RX applied；后续复测没有跳频。

## 新的 60 秒固定窗口

- 有效 DATA 416683 / 期望 481152，固件窗口累计 60.144 秒，约 6928 Hz；相对 8K 缺额 13.40%。
- RHD1 TX 窗口观测均值：触发 8000.38/s，发送启动尝试 7913.52/s，跳过 86.85/s。
- RX 入队前序号缺口约 972.10/s，合法收到约 6939.40/s。
- CRC 约 60.16/s，软件输入包队列丢弃 3.66/s，按键边沿队列丢弃 0。
- 重连、ACK watchdog、ACK 迟到增量均 0；频道切换、跳频均 0；最大记录静默 6ms。

各页统计边界不同，不能把这些均值直接相加；CRC 与序号缺口可能重叠。TX started 是 SDK 调用前计数，不等于已完成发射。

## 优化顺序

1. **先缩短 RX 全局关中断区。** RF_PHY.c:3449 将整个 demo_process_rx_pending_packet 包在全局 IRQ mask 内；短包解码 :2252 合成本机 payload 并逐位计算 CRC，之后 :2525 还做队列合并/复制。这些工作每个收到的输入包执行，会阻碍 RF 回调及时重新开启接收。将纯解码/CRC移到临界区外，只在提交共享队列时短暂加锁，并重新检查 radio generation，避免切频道后的旧包污染新会话。保持短按/释放顺序、USB 背压和 50ms 中立输入保护。代码路径已确认，是否解释主要损失仍需实测。
2. **补齐 RF 调用结果和接收空窗测量。** TX 分别记录 SetTxStart / SetTxParm 的失败数，不能将开始尝试当成功发射。RX 记录 SetRx 失败/重试数、回调入口到 rearm 完成用时、最长 IRQ mask 和回调耗时。用硬件周期计数及低频汇总，禁止每包串口输出。分别定位 TX 未发出、RX 未监听、CRC 与软件丢弃。
3. **再调整 RX 热路径和中断预算。** RF 回调本身已在 RAM，demo_fast_rx_packet 被内联在其中；但实际重新开启接收的 demo_arm_rx 在链接 map 的 Flash 地址 0x458a。测量后可将必要的 rearm 辅助函数放入 RAM。USB2 与 SDK BLEL 均配置 0xF0，需要确认实际 RF IRQ 路径及抢占关系后再调整优先级，不能盲目调整。ACK 定时器 0x80 的时序仍需保留验证。
4. **最后减少重复处理。** 已通过空口硬件 CRC 的短包被合成 v1 格式，计算软件 CRC，随后 capture_xinput_report 又校验同一份本机生成数据。可以建立受信的内部短包路径，或移除重复计算，但必须保留外部旧格式帧校验与输入边沿。普通相同按键状态合并输出，不能合并掉按下/释放边沿。

先保持频道 39、8K、ACK/空口保护参数不变，以缩短 RX 临界区作单变量 A/B；4K/8K、遥测开启/关闭作为后续对照。不要通过减少 ACK 或缩短已验证的控制包排空间隔来掩盖接收空窗。当前可确认 ADC 不阻止 RF 定时触发；仅靠消除 TX 的约 87 次/s 跳过也无法解释约 1000 次/s 的总缺额。
