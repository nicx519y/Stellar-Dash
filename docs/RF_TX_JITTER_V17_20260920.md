# TX 中断开销优化 v17

用户反馈 v16 更新后输入延迟正常，但 RF 丢包率抖动增加。截图中的完整记录 TX
约 122–123us；这是用户提供的结果，并非本轮重新采样。截图展示延迟表，部分
延迟记录数不能换算为空口丢包率。本轮没有读取设备或运行回归，仅代码分析及编译。

## 软件侧仍存在优化空间

v16 增加了常态 NSS 输入接收中断。此前 GPIO_A / SPI0 没有显式指定优先级，
而 RF TMR0 使用 0x80。SDK 的 PFIC_SetPriority 仅提供 bit7 抢占级。
SPI 工作没有被明确限制在 RF 定时提交同一抢占级，可能插入 RFIP_SetTxStart /
RFIP_SetTxParm 两步提交之间。NSS 接收中的两次 DMA 游标快照还会关闭所有中断。
这些路径对调度的干扰不能简单归类为空口干扰；但本轮没有量化它们贡献的丢包比例。

此外，主循环会对 NSS 已校验并发布的输入再次计算 CRC；RF 发送 ISR 每个时隙
处理电池、更新短 DATA 不使用的 busy watchdog 时钟，并重新计算固定 PHY 的
保护间隔。均可减少而不改变输入语义或空口时序要求。

## 实际改动

1. RF 模式 SPI0 和 GPIO_A 明确采用与 TMR0 相同的 0x80 抢占级，使 SPI 不能
   在 RF 定时处理执行中插入；保留 SDK 射频中断原有优先级。
2. DMA 游标快照只暂时屏蔽共享游标的 SPI0 / GPIO_A，保存并恢复其原使能状态，
   不再全局屏蔽 RF 定时器和 SDK 射频中断。输入快照原子发布仍保留短临界区。
3. CRC8 使用启动时生成的 256 字节 RAM 表，每个输入需要九次查表，替代原来的
   十八次 Flash 半字节查表。多项式仍为 0x07、初值 0、覆盖相同的九字节输入。
4. 主循环按绝对 DMA 位置识别 NSS 已接纳的输入，跳过这些不再可能发布的旧帧
   的重复 CRC。NSS 未接纳的兜底输入继续完整校验；后续源记录/命令继续解析。
5. 电池处理移出 RF 发送 ISR，在主循环 housekeeping 中读取最新快照，仍保留
   变化上报和五秒补报。桥接输入的电池处理也移到其输入发布临界区之外。
6. short DATA 不再更新未被使用的 busy watchdog 时钟；长控制包仍正常更新。
   5/7 字节对应的保护周期在初始化时预计算，发送时只选择对应值，保护值不缩短。

保留 v16 的 NSS 校验后直接发布输入、主循环旧帧防回退和按实际 RF DMA 包 tag
记录发送身份。没有退回主循环才更新按键的路径，没有新增独立 RF 包。
默认 8K、固定配对、频道策略、ACK 窗口、RF 包长和丢包统计口径均未修改。

这是软件开销优化，不能承诺将实际空口丢包率降低到某个数字。若剩余损失来自
无线干扰或接收侧其他瓶颈，这些修改未必能消除它。源分片缺失的问题也仍需独立
观察，不能用隐藏部分记录或平滑曲线作为成功标准。
