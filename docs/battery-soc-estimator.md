# XORA 充放电电量估算

实现入口：[估算器](../application/Inc/power/battery_soc_estimator.hpp)、[主控电源管理](../application/Src/power/power_manager.cpp)。`PowerSnapshot.soc_permille` 是屏幕、策略、测试记录及遥测的统一电量；MAX17048 原始 SOC 保留诊断用途。

## 校准依据

参考充入容量为 **7411mAh**，集中定义在 `BatterySocEstimator::referenceMah`，不是额定容量。来源文件 `XORA-device-logs-2026-10-25T09-51-26-571Z.json` 的 SHA-256、68 个汇总区间、电压拟合节点与限制保存在 [校准资料](data/charge-soc-20261025.json)。

按用户给定的近空到近满端点，汇总区间平均电流乘区间时长得到 7411.234849mAh；原日志首次显示 100% 时，对应归一化充入进度为 79.974722%。该文件手动结束且末状态仍为充电，校准不将它改写为硬件 Full。充电前约 3.2V 来自用户观察，首个已记录充电电压为 3.661V，未观测的插电瞬间不拟合。该曲线仅作校准资料，运行时不拿充电电压表查 SOC。

五分钟平均电流回放不等同于逐秒 ADC 记录，也不是独立的电量精度验证。BQ25895 的 ICHGR 是电池侧充电电流，步进 50mA，不能测反向放电；详见 [TI 数据手册](https://www.ti.com/lit/ds/symlink/bq25895.pdf)。不使用电源铭牌电流代替，不自动学习容量。

## 状态与计算

- 电池供电冷启动使用既有放电曲线；带电源冷启动只用一次原始 SOC。两种冷启动都先标记估算，稳定电池参考或确认满电后解除。无 Flash 持久化。
- 插电沿用上一电量；已确认欠压保护锚定 0%。STOP 保留对象 RAM，外部电源下继续现有一秒采样。
- 两端均为有效、允许充电且处于 Charging 的样本才作梯形积分；间隔必须大于零且不超过 2500ms。64 位累计分子保留千分点以下余数。缺样、故障或暂停时断开样本对，不补算。
- 5V/9V 切换不重置起点；增长速度跟随实际电池充电电流。普通充电最多 990‰。Full、允许充电且有效样本连续 30 秒确认后设为 1000‰；确认时长与充电测试由编译断言约束一致。
- 拔电保持 10 秒，再按每秒最多 1‰ 向放电曲线向下收敛；正常电压反弹不会增加电量。无历史起点的冷启动在稳定电池供电 30 秒后开始重新建立参考，收敛期间仍标记估算。
- 无效、暂停、缺样或弱电源标记估算。弱源下无充电电流时允许按电压向下收敛，不虚构负放电电流；恢复稳定电池供电参考或确认满电可解除不确定标记。
- 欠压仍直接按原始电压判断。充电故障、温度、输入范围、供电不足及负载限制沿用原门禁；显示收敛不能推迟欠压保护。

屏幕充电页和窄侧栏均不显示估算提示，充电页保留充电状态标签；无效值沿用原有显示规则。内部估算标记继续用于电量算法及遥测。日志消费统一 SOC，保留既有五分钟汇总/事件写盘机制，不新增逐秒写 Flash。

## 遥测兼容契约

所有新增数值为小端。公共定义见 [power_soc_telemetry.h](../common/power_soc_telemetry.h)。不修改按键包和固定频道策略。

| 24 字节电源载荷偏移 | 含义 |
| --- | --- |
| 0 | 版本 1 |
| 1 | bit0 有效、bit1 外部电源、bit2 快充、bit3 估算、bit4 低电、bit5–6 来源；bit7 必须为 0 |
| 2 | uint16 样本序号 |
| 4 | uint32 主控采样 uptime ms |
| 8 / 10 / 12 / 14 | uint16 电池 mV / SOC 千分点 / 输入 mV / 充电 mA |
| 16 / 17 | 充电状态 0–4 / 保留字节 0 |
| 18 | uint16 故障位 |
| 20 | uint32 累计样本年龄 ms |

来源 0=放电曲线、1=充电积分、2=冷启动估算、3=确认满电。状态 0=放电、1=充电、2=Full、3=故障、4=未知。

- STM32→TX：独立 SPI 命令 `0x0B`，`A5 + cmd + len + payload + sum8`。仅 TX 状态能力字节为 `D3` 时发送；旧 `D1` 不发送。使用非等待 DMA 提交，已有输入、IRQ/事件优先，正常最多每秒一份最新值。
- TX→RX：既有 AUX 类型 12，版本/长度校验，复用 AUX CRC32 完整性和分片机制。待发缓存合并为最新值，重复序号不更新接收时间，链路 generation 隔离旧数据。
- RX→HID：独立 32 字节 `RPS1` 报告；偏移 0 为 magic `0x31535052`，偏移 4 为上述 24 字节载荷，偏移 28 为前 28 字节 CRC32/IEEE。TX 对电源 AUX 记录施加 250ms 发送期限，载荷年龄保守计入空口预算；RX 再累计收包队列与 HID 等待年龄，过期清有效位。链路时钟按 625µs 换算。
- USB：保留 32 字节 MPW2 及原字段含义；flags bit7 显式声明估算元数据，bit6 表示估算，原 reserved 低 2 位为来源、高 30 位为采样年龄（饱和）。原 timestamp 仍为生成报告时主控 uptime，消费者用 timestamp 减年龄得到样本时间。
- 新监视器优先主控 SOC，重复样本不会刷新新鲜度；超过三秒显示 `Stale`，连接/session 重建清旧快照。收到新格式后，旧电压报告不能覆盖它，过期也不偷偷回退。仅旧电压格式时显示 `Voltage estimate`，充电状态为 `Unknown`。

## 验证与人工验收

算法与回放：`python -m unittest tools.tests.test_battery_soc_estimator`。电池保护、负载限制、主控集成和睡眠充电显示使用对应 `tools/tests` 定向用例。协议生产者/消费者作源代码核对，TX/RX 编译、监视器类型检查及构建不代表协议运行验收。

本次不运行 RF/监视器数据格式模拟测试、自动回归或设备采样，不恢复自动跳频，不烧录或部署。后续人工验收：欠压睡眠分别接入两类电源、中途换源、部分电量起充、拔电/快速插拔、带电源重启、Full 持续确认，并比对屏幕与 USB/RF 监视器的统一 SOC 和估算/过期状态。

构建布局将屏幕和日志命令的只读标签、调色板、查找表归入现有 DTCM 常量区，沿用 `_siui_rodata` 到 `_eui_rodata` 的启动复制。DMA 缓冲、堆栈预算、Flash 分区及烧录流程不改动。布局检查同时验证常量加载镜像、启动复制、故障保留区和电池记录器位置。
