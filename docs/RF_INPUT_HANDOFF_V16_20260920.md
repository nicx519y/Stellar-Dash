# TX 输入交接与实际发送身份 v16

用户 v15 截图仍有部分源记录缺失，TX 阶段约 0.43/3.01/3.22/3.50/6.40ms，
而 STM32 阶段和 RX/USB 阶段较短。本轮仅修改 TX，已编译；未读取设备、
未运行回归、未烧录。实机验证由用户进行。

## TX 列到底包含什么

当前 TX 时间是同一匹配发送尝试的 `RF 启动时间 - 首帧 SPI NSS 结束时间`，
不是空口传输时间。此前 SPI 完成中断只存时间，正常输入发布要等主循环
`rfm_spi_bridge_poll()` 消费 DMA 缓冲。期间定时 ISR 可以继续发送旧快照，
所以稳定接收率不能说明按键状态及时更新。

这段时间包含 SPI 解析排队、等待定时发送时隙，以及可能发生的 ACK 接收窗、
控制事务和射频调度等待。普通 8K 时隙是 125us，不能把数毫秒当作一个正常
发送周期。截图本身不能把 6.40ms 精确分摊给以上各项；本轮没有声称完成了实测归因。

## 直接处理主循环交接等待

- NSS 上升沿始终处理完整输入事务，不依赖测量是否开启。
- 仅接受长度明确为 14 字节（输入）或 38 字节（输入 + 既有 SPI 源记录）的事务；
  只复制首 14 字节，检查帧头、长度、外层校验和、输入 CRC8，并复核 DMA 未覆盖。
- 校验通过即发布 10 字节最新输入及事件元数据，让下一次 RF 定时发送能读取新状态。
  不在 NSS ISR 发 RF、不解析诊断分片、不处理电池、不回复控制命令。
- 相关热路径放入 RAM。主循环继续消费控制和源记录，保留经过校验的输入兜底路径。
- 两个输入入口共用绝对 DMA 字节位置判新：主循环即使稍后读到旧帧，也不能覆盖
  NSS 已接收的新帧。不再用 8 位采样序号判断这两个入口的先后。
- DMA 重置与 NSS 快速路径互斥；休眠时关闭 NSS 接收，恢复初始化后重新启用。
  测量开关不再控制正常输入中断是否启用。

## 发送身份修复

此前 `short_note_launch()` 按全局最新事件 tag 记录发送，但 RF 实际使用的是
先前构造的 DMA 包。当 SPI 最新事件与已构造的包不同，会给错误事件记下一次
发送。另一个问题是重复消费 RF 输入快照也会调用 `short_note_input()`，可能用
旧快照重新初始化事件槽，丢掉其源记录和发送尝试。

现在事件槽只在 SPI 接纳输入时创建；RF 消费快照不再重置事件槽。
发送成功后从该次 RF DMA 包读取 tag，再记录对应的 wire sequence 和 launch。
记录始终跟随实际包，不按全局最新键值或最新事件猜测归属。

这修复了静态可见的交接/关联路径，但有限分片传输仍可能丢失源记录，首帧
丢失、仅记录前六次尝试等限制也仍存在。不完整行继续显示，不补零、不过滤。
本版本未承诺截图全部缺失或全部毫秒尖峰已经实机消除。

## 交付

SHA256SUMS.txt。仅更新 TX；STM32 沿用 v13，RX 沿用 0x1913，监视器无需更新。
