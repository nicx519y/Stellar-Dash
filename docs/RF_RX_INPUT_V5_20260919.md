# RX input v5：降低输入处理开销

## 实现

- 删除仅写入、没有消费者的 pending-input 单槽数组、valid 与奇偶 generation。实际输入 FIFO 与 radio generation 保留。
- 短 DATA 通过空口硬件 CRC 后直接生成私有输入状态，不再为这份内部数据计算无人使用的软件 CRC；CRC 字节置零。外部旧格式帧仍由旧格式 decoder 校验 CRC。
- XInput 消费采用两段短临界区：先复制 FIFO 输入/时间戳/代次，然后开中断执行纯按键映射，最后校验代次并提交状态、延迟统计及 XInput report。
- FIFO 各项记录 radio generation；旧代次残留会被丢弃。中立输入/清空 FIFO 时增加 input epoch，防止构包过程中发生 reset 后恰好复用同一 tail 下标，导致旧按键复活。
- 若构包期间已有待发送报文，保留 FIFO 边沿供下一次处理；USB 忙/失败重试路径保持原行为。50ms 中立输入保护保持。
- 诊断 build ID 0x1905，RHD1 布局不变。输入消费最大耗时表示快照和提交两段中较长的临界区，不包含开中断构包；旧 v4 指标包含连续构包段，两者均不是每包平均或 P95。

## 验证

30 项 Python/原生 C 行为及冻结烧录契约测试通过。包括全部 262144 种 18 位按键组合，XInput 报文边界、扳机与保留字节；纯构包开中断断言；构包时重连、输入 epoch 回绕/中立清空、已存在待发送报文；短按/释放顺序与 USB 失败重试；旧格式坏 CRC 拒绝。
RX 固定配对、正常配对分支均编译通过。主机测试不代表实机吞吐或输入完整性验收。

## 交付与实测边界

只更新 RX，使用 `.hbox/rf-rx-input-v5-20260919/RX.hex`。TX 保持 dd46370d…，STM32 不更新；8K、固定频道 39、关闭自动跳频、ACK/空口保护参数均不调整。
RX.bin SHA-256：`adfe8f80e744fc7d3fc1a1390fbe7bea9e4e8acf38655fa2c24c72e08098f531`。

待用户烧录并验证 build ID 0x1905 后，与 v4 的约 7540 Hz、5.75% 目标缺额、约 132/s 原始包队列丢弃对照。不能仅以入队前接收率增加判定输入链路通过；须同时看解码提交速度、软件丢弃、按键行为和临界区耗时。

本轮没有执行烧录，未修改保护位、锁定状态或已验收烧录流程。

## 实机结果（用户已烧录）

已确认 RX build ID 0x1905，两端配置 applied，自动跳频关闭、频道 39。
60 秒采样的固件统计窗口合计 60.238 秒：有效包 454248 / 期望 481904，加权约 7540.89 Hz，目标缺额 5.74%。与 v4 的 7539.76 Hz / 5.75% 相比，入队前接收吞吐基本不变。

| 指标 | v4 | v5 |
|---|---:|---:|
| 原始包软件队列丢弃 / 秒 | 131.57 | 0 |
| 短包解码提交 / 秒 | 7407.16 | 7532.93 |
| 原始包队列启动后最高占用 | 15 | 5 |
| CRC 事件 / 秒 | 43.88 | 26.92 |
| 输入提交最大临界区 us | 34 | 24 |
| 输入消费最大临界区 us | 35 | 31 |

各页窗口及采样时间不同；CRC变化不能直接归因代码，最大值不是平均/P95。v5 输入消费采用分段临界区，其指标含义见上文。

v5 窗口重连、跳频、RX SetRx 失败、ACK fail/迟到/watchdog、原始包队列及后级按键边沿 FIFO 丢弃增量均为 0。最大记录静默 6ms。
TX 约 7999.90 次/s 触发、7916.97 次/s 启动尝试、82.93 次/s 跳过；RX 序号缺口约 374.58/s，CRC约26.92/s，说明剩余的约5.7%目标缺额仍主要在发送启动到RX有效接收之间。下一阶段需补 TX SDK 失败/实际发送时序、RX 普通短包回调耗时分布与全局中断屏蔽测量，不能用 SDK 调用尝试数当成功发出数，也不应盲目缩短 ACK 或发送保护。
