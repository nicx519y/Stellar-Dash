# connect-monitor 周期性统计停更修复（v25，2026-09-22）

本次只修改监视器。RX 继续使用 build ID `0x1924`，TX、STM32、空口包及 RF 参数不变。

## 静态分析

- `hid-telemetry-source.ts` 的 1 秒维护任务把 RX 统计租约续期、延迟租约续期和 HID `GET_REPORT` 配置状态读取放在同一串行控制队列中。配置已经 Applied 时仍每秒读取状态；若该读取等待 HID 驱动，后续续租只能排在它之后。RX 的统计租约 3 秒过期会停止 RHM1 上报，而正常按键输入不依赖这条统计通道。这是能产生周期性遥测停更的代码路径，尚未经实机确认为截图唯一原因。
- 趋势图之前把缺失样本前后的两个点直接连成斜线。数秒遥测断档会看起来像接收率匀速下滑、丢包率匀速上升；这些中间值并非 RX 实测。
- RX 的 5 秒串口统计函数在交付构建中由 `SERIAL_LOG=0` 关闭，不能解释当前周期性现象。图中未见相应频道事件，不能仅凭该图认定自动跳频发生。

## 修改

- 稳定 Applied 且 RHM1 正常流动时，只续必要的 USB 租约，不再每秒执行配置 `GET_REPORT`。配置仍在应用中或 RHM1 连续 3 秒未到达时，才按至少 2 秒间隔读取状态并沿用已有恢复逻辑。
- 趋势图遇到大于 1.6 秒的 RHM1 时间缺口时断线，不为缺测区间插值。面板超过 2 秒没有统计时显示“统计停更”和持续时间，避免把旧数值显示成当前值。

## 验证边界

只执行 TypeScript typecheck 与 monitor build；按用户要求未运行回归、未采集设备、未烧录。用户实机验证时，观察卡顿期间是否出现“统计停更”及 Windows/游戏按键是否同步停顿。如果只有统计停更，应继续按 HID 统计链路排查；如果按键也停顿，应结合 RF 序号缺口和 TX skipped/window 继续查实际无线收发，不能把图表修正当作 RF 性能修复。
