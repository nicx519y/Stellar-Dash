# RX v32：修复 v31 的接收与延迟记录回退

状态：修正版 RX build **0x1932** 已编译；未执行回归、设备采样或烧录。8K/125µs 实机验收仍未通过。v31（0x1931）有用户报告的接收率下降及大量缺源记录，应视为存在回退。

## 已有证据与归因边界

只读取已有 `monitor-events.jsonl`，采用截至 timestampMs=1790089605164 的记录：

- RHD1_0 确认 RX=0x1931；辅助待处理队列当前/最大水位都是 15/15。
- RHD1_1 累计辅助队列丢弃 31,322，CRC 571，ACK late/watchdog 为零（不同诊断页时间略有差异）。
- 最后一个 RHM1_C 窗口 103ms，接收 613、期望 824，输入缺额 25.6%；用户另一个截图显示 33.30%。这是输入缺额，不等于全部来自空口 CRC 错误。
- 新截图 251 次变化、141 完整、110 部分；大量行 RX/USB 已有值、ADC～TX 缺失。辅助记录需要多个无线分片完整重组，接收缺口和软件辅助队列溢出均会降低匹配成功率。
- 日志未包含 RXP1 完整流水线诊断，无法由现有数据定量分摊每个阶段占用。不能宣称下列任何单项已实机证明是 33.30% 缺额的唯一原因。

## 本次修改（仅 RX 与验证文件）

1. **消除逐中断的隐藏 Flash 调用。** v31 ELF 证明 `RXP_Begin` 返回结构体时调用 Flash `memcpy`；RF 回调在接收重启之前执行它，USB/定时器也执行。改为直接填写调用者的作用域对象。
2. **缩短计时临界区。** 记录器保存周期数，直方图使用 RAM 周期阈值、至多四次比较；微秒换算在每秒快照冻结后开中断执行。结束作用域/临界区直接调用已持锁记录器，避免重复禁用/恢复中断。计数、全部样本、125µs 超标和 RXP1 v1 输出语义保留，不通过停用测量或抽样隐藏尖峰。临界区指标仍不含其自身记录尾部开销，不能当完整硬件 WCET。
3. **修复辅助消费能力限制。** v31 每次 RF_Service 只消费一项；v32 一步仍只处理一个分片，但可连续分步消费，单次最多 15 项、达到 125µs 经过时间预算后不再启动下一步（单步可被 RF/USB 抢占而超出预算）。分片常用处理和出队代码置 RAM，分步间中断开放，不挪进 RF 回调。仍保留队列丢弃计数；队列容量与 RF/ACK 时序不变。
4. **减少后台屏蔽接收的时间。** pipeline 状态发布、元数据发布及必要的小函数置 RAM；延迟 HID 报表只在短临界区复制事件快照，编码/时间换算/提交放在锁外，提交后用 session/row/revision 复核。源匹配的有界发布路径全部 RAM。
5. **减少报告复制成本。** 自然对齐的报告用合法 may_alias 字复制/清零，保持四份待发、一份独立在途和 500µs 拥塞规则。
6. **修复重复报告污染延迟身份。** 只有首份为某个事件准备的报告绑定该事件。后续相同事件的重复报告被拥塞丢弃时，不再把先前在途报告的测量记录标为失效。首份本身丢弃仍明确标记不完整，不借后续报告补造时间。

空口 v5、正常 TX、STM32、USB HS 配置、ACK 所有权及烧录/IAP/保护状态未作本轮修改。与现有 v27/v28 TX 配套；本轮不要求更新 TX/STM32。

## 用户实机验证

使用既有 RX 升级入口更新本目录 `RX.hex`，设备诊断应显示 0x1932。不要使用 TX/IAP 烧录入口处理 RX 镜像。重启已构建的新版 connect-monitor，可查看 RXP1 流水线统计；旧监视器仍可读取原延迟表和 RHD1。
