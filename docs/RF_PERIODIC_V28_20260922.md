## 代码确认并修正的开销

- TX `channel_service()` 原先无论是否存在事务，每625μs预约 TMR2 在2μs后执行。TMR2 本身全局屏蔽中断运行频道状态机，并重新设置定时器。稳态普通 ACK 已由 TMR1负责，该1600次/秒空转没有业务作用。现在普通模式空闲不再主动唤醒，最后一次事务回调结束后不再安排空闲轮询；实际频道事务和快速模式保留定时处理。
- `demo_active_hop_cmd()` 先判断是否有事务，再读截止时间；普通不请求 ACK 的 DATA 不查询控制包。
- 故障注入关闭时，发送与完成回调不再为无效检查读取共享时钟。注入开启仍走原入口，包括期限处理。
- SDK 接纳普通输入后，不再为两个无时间工作重复读取时钟。保留原本的 `want_ack` 清除和快速恢复提交期间 `fast_data_sent` 设置；真正控制包仍调用生产 manager/fast 引擎。

这些路径与125μs发送节拍竞争，减少其占用可增加调度余量。独立 SPI 与 RF 节拍的相位漂移可能使开销集中表现为波峰，但现有证据尚未确认这是9.1秒周期的来源。未调整 SPI 中断优先级、5/7B保护、DMA缓冲、ACK超时、频道阈值、输入顺序或图表统计口径。
