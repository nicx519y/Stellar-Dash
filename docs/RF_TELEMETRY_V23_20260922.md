# v23：按键正常、报表间歇停更

本次修改 RX USB 遥测调度及 connect-monitor。RX build `0x1923`，空口仍为 v4，匹配既有 v22 TX；TX/STM32 不改，不改变 RF 包长、速率、频道策略或烧录入口。

## 从代码确认的原因

1. `RF_main.c` 在统计之前调用 `RF_TrySendTraceReport()`，诊断可以先占用 vendor HID IN 端点。统计到期后，不论提交是否成功，都推进外层周期；一次 busy 就再等一个完整周期。
2. `RF_TrySendTelemetryReport()` 内部又先发 RHD、旧延迟、输入快照、频道分数及 RSSI；任何一个发送成功便返回。配置的 telemetry period 实际是“混合报文机会”，不是接收率/丢包率 RHM1 的保障周期。
3. `demo_hid_elapsed_ms()` 在 USB 提交前修改统计起点。提交失败保留了计数，却丢失这段时间，造成下一次计数/窗口错位。
4. 上轮把同步 HID 操作搬到 worker，保护了 Electron 主线程，却仍会阻塞同 worker 的统计帧回调/转发。
5. 报表每次更新都以 `notMerge=true` 重建 ECharts 配置并调用 `resize()`，造成额外布局工作。IPC 积压每次收到确认后还要等下一固定周期才能继续排空。

按键显示走独立 XInput 查询，不依赖这些统计帧；因此按键流畅不能证明报表通道没有阻塞。这些为静态代码缺陷，未做设备采集，不能归因实机全部停顿或量化各项贡献。

## 修复

- RHM1 到期优先获得下一个空闲诊断端点；busy 时主循环重试，提交成功才推进外层周期。正常输入处理保持在其之前。
- RHM1 函数只发统计。其他 USB 诊断移到统计间隙：RHD 保留 500ms，输入快照/频道分数/RSSI 按配置周期的 3/5/4 倍独立计时。它们不再替代统计帧。
- 统计时间起点与计数在成功提交时一起结算；失败不改起点、不减计数。配置刷新周期仍由用户选择 100/250/500/1000ms，不做插值或篡改丢包值。
- HID 使用安装版本提供的 `HIDAsync`、`devicesAsync`：枚举、打开、控制读写、关闭均异步；控制串行且有上限，维护任务不重叠，断开后的旧句柄结果丢弃。接收回调和转发定时器不等 GET_REPORT 完成。
- 主进程/HID worker 在确认上一批处理完成后立即继续发送已积压数据，保持最多一批在途和队列上限。
- ECharts 合并更新数据，尺寸变化由 ResizeObserver 处理，不再每个统计点强制重建/resize。

这些修改增加的是 USB 报表调度保障，不新增空口包或 RF 时隙。PC 改动不能代替 RX 调度修复，需一起使用。
