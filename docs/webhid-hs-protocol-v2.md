# XORA 单一高速 WebHID V2

本文件描述当前工作区协议，实机验收状态见 [实施记录](webhid-hs-implementation.md)。三端必须配套升级；不支持 V1 或 FS 配置回退。

## USB 能力

接口 0，端点 IN 0x81/OUT 0x02，VID/PID/Usage 保持现有标识；bcdDevice=3.00。输入/输出均为 1024 字节、无 Report ID。HS wMaxPacketSize=1024、bInterval=1；FS 端点为合法 64 字节，配置数据 NAK，只保留 EP0 能力查询。

打开后读取只读 Feature Report 0（32 字节），多字节整数统一 LE：

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 4 | magic 0x32485758 |
| 4 / 6 | 各 2 | 协议版本 2 / 报告长度 1024 |
| 8 | 1 | USB 速度：0 未连接、1 FS、2 HS |
| 9 / 10 / 11 | 各 1 | 桥接 ready / fault / 窗口 8 |
| 12 / 16 | 各 4 | SPI Hz / SPI 连接代次 |
| 20 / 24 / 28 | 各 4 | 端口首错 detail / produced / consumed；正常时全零 |

fault：0 正常、1 未协商、2 未提交、3 未分类完整性/协议错误、4 块 CRC 错误、5 块长度/版本错误、6 块序号/代次/窗口错误；`0x10 | port_status` 表示 DMA/端口错误，低四位为 `usb_board_status_t`。保留当前连接的首个错误，PREPARE/STOP 清除。网页能力验证通过前不发送认证或配置报告。非 HS、版本不匹配、未就绪均明确报错。

端口故障时，Feature 偏移 20/24/28 的三个 LE32 字段发布首错诊断：detail、produced、consumed。detail 的四个字节依次为来源、SPI 标志、FIFO 计数、TX armed；来源 1=RX FIFO、2=DMA 差值超过一圈、3=软件环容量不足、4=SPI IRQ FIFO、5=环写入容量不足、6=NSS ISR FIFO。来源 5 的后两字段为写入长度和软件环占用，其他来源为 DMA 生产/消费计数。无端口故障时三个字段全零。报告仍为固定 32 字节，诊断不含任何报告载荷、密钥或配置数据。

## 安全报告

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 / 1 | 各 1 | 版本 2 / 类型 |
| 2 / 4 / 6 | 各 2 | flags / 载荷长度 0..996 / 保留零 |
| 8 / 12 | 各 4 | 方向独立递增序号 / 加密会话代次 |
| 16 | 996 | 有效密文载荷 + 零填充 |
| 1012 | 12 | AES-256-GCM 标签 |

整个 16 字节头是 AAD。bootstrap 代次/标签为零，沿用现有直连会话建立流程。错误标签、非法长度/填充/flags、代次或序号错误不能继续原会话。

HKDF-SHA256 info 前缀为 `XORA WebHID v2\0<sessionId>`，随后分别派生 `browser-to-device`、`device-to-browser` 密钥及 nonce 前缀。盐前四字节 LE 为会话代次，零映射至 1；它与 SPI 代次是不同字段。黄金向量见 [V2 向量](../common/test_vectors/webhid_security_v2.json)。

业务 RPC/事件保留原消息语义。通用流头 15 字节，偏移 13 为 uint16 chunk 长度，最多 981 数据字节；图片报告 0x31 最多 996 数据字节。开发测速报告 0x32 内层为 run ID、offset（各 uint32）及最多 988 数据字节。

## SPI 配置块

启动/IAP 使用原 0x5A 控制帧及 /256。新配置同步字 0x5B，头 32 字节，最多携带 3 个完整 HID 报告，总长 32..3104，不超过 DMA 4095 字节限制：

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 / 1 / 2 | 1 / 1 / 2 | 0x5B / 版本 2 / 总长度 |
| 4 / 8 | 各 4 | 连接代次 / 块序号 |
| 12 | 4 | 首个报告累计编号 |
| 16 | 4 | 已接收报告累计 ACK |
| 20 | 4 | 可接收报告绝对上限（已释放数 + 8） |
| 24 / 25 | 1 / 3 | 报告数 / 保留零 |
| 28 | 4 | CRC32，覆盖头 0..27 和所有报告 |

ACK 不得倒退或超过已发送数；credit 不重复释放容量；代次不符拒绝。重复最后一块必须 CRC 一致，不重复交付。底层取得副本后才提交发送；消费者取得副本后才释放接收槽。数据最多占 7 槽，控制可用第 8 槽。受加密序号约束，不重排已提交报告。

HS_CAPS/PREPARE/COMMIT/STOP/STATS 操作由共享头定义，空配置块完成探测。当前候选为 SPI4 120 MHz /8=15 MHz；7.5 MHz 可配置，尚未板级比较。WCH [CH585 手册](https://www.wch-ic.com/downloads/CH585DS1_PDF.html) 10.5 节的输出延迟最大 18 ns 已超过 30 MHz 半周期 16.7 ns，当前模式不选择 30 MHz。15 MHz 仍需核对主机建立时间、板级延迟、温压裕量及可靠性。

尚未实现异步双缓冲流水线或完成吞吐/恢复验收。1024 字节 HS 枚举不表示整条链路达到 480 Mbit/s。
