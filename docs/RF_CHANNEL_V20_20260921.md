# RF v3 自动选频与切换交付（v20，2026-09-21）

本次实现 TX/RX 和 connect-monitor，STM32 不变。已完成代码静态检查和构建；没有运行回归、采集设备、烧录或实机验收。性能目标不是本次已测得的结果。

## 模块边界

- `TX/APP/rf_channel_policy.c/.h`：按数量加权的质量窗口、历史、候选、冷却、隔离、观察和回退决策。不访问 SPI、USB、SDK 或 `g_demo_*`。
- 两端 `APP/rf_channel_manager.c`：编译共同的 `Common/include/rf_channel_engine.inc`。会话、事务序号、截止时间、预约、确认、探测和恢复由一个管理器拥有。
- 两端 `APP/rf_channel_radio.c`：编译共同的 `rf_channel_radio_impl.inc`，使用 TMR2 执行截止动作；排空、切换、建立分别推进。
- `Common/include/rf_channel_protocol.h`：v3 参数、包字段、时序版本、分速率验收位图和准入规则。
- 两端 `RF_PHY.c`：现有收发入口以及 SDK 适配、事件交付、动作执行、诊断快照。旧 TX 排名/跳频实现及 RX 旧评分实现已删除。

管理器/射频 API 头文件放在 Common，不复制两份声明。现有 Makefile 的 `APP/*.c` 自动纳入新模块；没有修改构建或烧录入口。

## 输入、事务与回调所有权

普通输入保持完整当前状态。RX 原始输入使用 latest mailbox，USB 待准备报告也只保留最新状态；不回放积压的按下/松开。已交给 RF/USB DMA 的数据不覆盖。50ms 中立释放优先保留至 USB 提交。

附带诊断分片单独重组；其丢失不拒绝有效输入。合并次数、RF 序号缺口、CRC、TX 启动失败和诊断 FIFO 丢弃分开计数。DATA 序号只在 `RFIP_SetTxStart/SetTxParm` 均返回成功时推进；这表示 SDK 接纳，不证明空口到达。

连接态 TX 输入/事务的发送结束不再由无身份的 `TX_FINISH` 推进；TMR1 按实际包长及首包保护打开 ACK 接收。RX ACK 的 DMA 结束也由对应保护定时器负责。迟到的 SDK 完成回调不能结束新事务；10ms watchdog 仍作为异常兜底。连接/配对原有收发入口保留。

切频取消旧 ACK 定时动作、推进 radio generation、调用 Stop/SetParam、等待建立保护、恢复收发。SDK 内部 PLL 就绪时间无法由现有头文件确认；SetParam 成功只表示设置成功。Connected 仍需要合法 DATA/ACK，VERIFY/恢复不会仅因设置频道成功而公开为已连接。

TMR1/TMR2 使用与现有 RF 定时器一致的 `0x80` 优先级，SDK 操作在有界临界区串行执行；等待排空/建立通过下一次定时动作完成，不在关中断区等待硬件建立。保留既有短包到控制包的 300us 排空保护。

## v3 空口约定

长度仍为普通输入 5B、附带输入 7B、短 ACK 5B、事务/扩展 ACK 12B；没有新增独立诊断发送时隙。

CONNECT 校验协议 v3、固定配对地址、发现频道和 profile 版本。原 CONNECT 字段 7 在 v3 表示 8 位会话标识；CONNECT ACK 回显会话。DATA 初始序号为零，测量的完整序号继续通过既有附带 anchor 建立。

12B 频道事务的 10B payload：

| 偏移 | 内容 |
|---|---|
| 0 | PREPARE / CONFIRM / RECOVER |
| 1 | target channel |
| 2..3 | 距共同生效点的微秒倒计时（LE16） |
| 4 | transaction sequence，独立于 DATA sequence |
| 5 | old channel |
| 6..7 | baseline loss / probe dwell（LE16） |
| 8 | 高半字节为 session 高 4 位，低半字节为 profile |
| 9 | 高半字节为 session 低 4 位，低半字节为 mode |

控制包头第二字节为独立请求 token。CONFIRM 倒计时在实际调用 SetTxStart 前刷新，重复发送指向同一截止点。RX 首次确认后不重新定时。新会话、错误事务序号、错误频道的包不能推进原事务。

短 ACK：头/请求序号 2B、received 1B、expected 2B。计数超出短 ACK 容量或有控制回执时使用 12B 扩展 ACK，不增加回复次数。头中的 quality-valid 与 LINK_OK 独立；无有效质量计数仍可证明合法链路。CRC 不再次加到序号缺口上。

事务 ACK 回显 transaction sequence 和 session。PROBE_RESULT 的接收数为 byte 4（1ms 内最多 8 个机会），session 为 byte 5。已提交 RX 仍可幂等确认相同 RECOVER，避免最后确认丢失后永久分离。

## 策略

七频道保持 10、16、22、24、28、34、39。质量由 RX 入队前有效接收/序号缺口计数提供，TX 主循环聚合；IRQ 只写有界记录，不排名。质量事件队列溢出时该统计窗口标为无效。

- 连续 3 个 1s 窗口损失 ≥5% 才普通切换；连续 2 个 <2% 视为恢复正常。
- 当前良好时不追逐排名。可信历史 60s 有效，按有效数量加权，未知显示 Unknown。
- 候选须改善 ≥2 个百分点且相对改善 ≥25%。无可信候选按固定轮转选一个未知频道；普通冷却 30s，失败隔离 60s。
- 保留合法 ACK 但连续 3 个 ACK 窗口损失 ≥50% 时，可独立触发紧急协商；只有实际开始才消耗 5s 紧急间隔。
- 事务开始前冻结基线。切换后观察 3s；至少两个有效完整窗口且达到改善要求才接受。连续两个窗口比基线差 ≥2 个百分点提前结束。
- 未改善/样本不足使用新事务回退；回退协商失败进入共同发现。快恢复提交属于恢复，不以未知基线再启动选频试用。
- 重连不清除历史、隔离、普通/紧急冷却。8 位事务序号按半区间判断先后；本地微秒截止时间用有符号差值，历史和冷却及时过期。

PREPARE/CONFIRM 各最多 100ms，等待期间继续最新输入。首次 CONFIRM 建立 5ms 生效预约，TX 比 RX 预约多留 125us 建立余量。失败后旧/新会合最多 200ms；恢复中收到重复消息或进入 VERIFY 不能重新延长这个总期限。

维护准入使用 101 个 10ms 桶，保守覆盖任意滑动一秒。普通 ACK 预留接收窗、一个报告周期的调度余量及首包开销；事务额外计排空开销；短测计完整 1ms 离开时间。合计预留超过 30ms 时推迟维护。恢复/发现属于故障过程，不拿这个预算作为延迟承诺。面板显示的是预留上界，不是硬件实测占用。

## 时序能力说明

profile 1 的公开 SDK 依据：`wchrf.h` 中 `sendTime` 为 `N*0.5us + 24us`；`CH58x_timer1.c/CH58x_timer2.c` 定时单位为系统时钟。SDK 射频内部为库，不能由这些定义推出 SetParam 后锁定时间或 IRQ 最坏抖动。

当前 2M 工程保护：

| 项目 | 当前配置 | 是否实测验收 |
|---|---:|---|
| TX 同频道 5B / 7B / 12B DMA 保护 | 104 / 112 / 132us | 本版组合未验收 |
| 换频后额外建立等待 | 100us | 否 |
| 换频首发 sendTime | 120 half-us，即 84us SDK 建立参数 | 否 |
| 换频首发 5B / 7B / 12B DMA 保护 | 160 / 168 / 188us | 否 |
| 在途操作最大排空等待 | 1000us | 否 |
| TX 回调/控制过渡排空间隔 | 300us | 保留已有工程保护，非硬件最坏上界证明 |
| RX ACK 预约 | 收包时间戳后 200us | 本版组合未验收 |
| RX ACK DMA 保护（正常 5B / 12B） | 120 / 148us | 否 |
| 预约偏差余量 | 125us | 否 |

分速率 profile：

| 速率 | 报告周期 | 拟验收 ACK 间隔/窗口 | 本次运行 ACK 基线 | 后台短测 |
|---|---:|---|---|---|
| 1K | 1000us | 40ms / 1000us | 100ms，保守接收 | 禁用 |
| 2K | 500us | 20ms / 500us | 100ms，保守接收 | 禁用 |
| 4K | 250us | 20ms / 500us | 100ms，保守接收 | 禁用 |
| 8K | 125us | 20ms / 500us | 100ms，保守接收 | 禁用 |

`RFC_*_TIMING_ACCEPTED` 及对应 `RFC_*_ACCEPTED_RATES` 位图均为 0；必须双方协商对应能力。位图 0..3 对应 1K/2K/4K/8K。更改速率只能使用本速率获准的能力，不能从 8K 验收推定 1K。速率切换后若对端未协商该能力，继续保守运行。

短测准入保守开销为 `2×300 + 2×100 + 2×180 + 125 + 2×报告周期`：8K 为 1535us，4K 为 1785us，已超 1ms，尚未加入有效测试窗口。因此本版不能宣称无感短测，也不能仅降低探测频率或翻验收位开启。需要先实测并修订 profile/硬件调度，使最坏完整间隔通过，剩余窗口仍有两个完整输入机会。

已编译的可选短测路径：旧频道预约；TMR2 切出、建立后接收；返回动作在射频 ready 回调中直接预约到 TMR2；候选零接收仍按时返回；旧频道下一次扩展 ACK 交结果。结果丢失为未知，零接收为失败。至少 64 样本、8 次、跨 2s 才可能进入试用，未改善候选隔离。硬件失败直接恢复，不把其计为频道干扰。

已编译的可选快恢复：合法请求失败后原请求起点 +2ms 重试；自动模式两个备用频道分别最多 12ms，按已提交主频道索引 +1/+3 派生。RX 静默 2ms 后按主 2ms / A 4ms / B 4ms 会合，总期限 80ms。TX 匹配 ACK 提交，RX 随后普通 DATA 提交；恢复探测不改变备用计划。固定模式不扫描备用频道。当前未验收，实际使用原 100ms ACK 逻辑窗口、500ms 合法 ACK 兜底和共同发现路径。

## connect-monitor 诊断

原 auto 开关和手选频道入口保留。新增独立 `RfChannelStatus`，显示阶段、主/候选/备用频道、短测禁用原因、维护预留、前后质量、样本来源/年龄、计数和输入间隔。未知频道不再显示为零损失。

TX 每秒的 54B 状态经已有 7B 输入附带通道分片；不新增空口发送时隙。RX 本地数据通过 USB `RHF3`（magic `0x33464852`）32B 页上报，不经过 RF。不要与旧时钟同步 `RHC3` 混淆。

页 0..2 是同一 TX 快照，页 3 是本地输入间隔/过渡缺口/软件合并，页 4 是版本不匹配、RX 阶段和本地错误，页 5 是切换前输入间隔、跨切换间隔及 RX 预约/射频/零接收失败计数。约每 250ms 尝试一页；USB 忙会推迟。TX 快照 age 过期不作实时结论。RHF3 不计入输入率/丢包率。

`first packet` 从切频建立结束到第一包有效 DATA；`across switch gap` 从之前最后有效 DATA 到下一有效 DATA。不能用 first packet 单独证明整个切换满足 1ms。总体 max gap 和过渡序号缺口保留，不从体验统计扣掉切换损失。合并次数是软件阶段覆盖计数，不等于独立输入事件损失数。

交付目录 `.hbox/rf-channel-v20-20260921/` 包含匹配 TX application、RX.hex/bin、monitor 构建资源、构建日志、manifest 和 SHA256SUMS。STM32 沿用当前固件。未修改 IAP、任何保护位或锁定状态，未执行烧录。

TX 继续现有 `python tools/hbox.py flash tx`；本次没有执行。不要把 TX application bin 当作地址 0 的整片镜像。RX 由用户按既有流程烧录。监视器关闭旧进程后，在 `connect-monitor` 执行 `npm start` 使用已构建资源；不会自动替换正在运行的进程。

建议用户首先关闭 auto，手动切两个频道并返回，确认输入持续更新和跨切换最大间隔；再开启 auto，核对三坏窗口→试用→接受/回退。之后覆盖测量开关、1K/2K/4K/8K、两种上电顺序、单边重启、确认丢失和遮挡恢复。短测/快恢复保持关闭，直到相应时序 profile 实机验收通过。P95、最大恢复时间、两小时 8K 稳定性均等待用户验证。
