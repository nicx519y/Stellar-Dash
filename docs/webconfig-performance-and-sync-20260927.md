# WebConfig 实时反馈与同步调整（2026-09-27）

## 当前结论

当前链路是 USB HS、1024 字节 HID 报告、窗口 8、SPI 7.5 MHz。Windows USB Hub 的只读连接信息确认速度为 HighSpeed，端点 0x81/0x02 的最大包长为 1024、bInterval=1。

这不代表全链路最大有效吞吐已经验收。SPI 7.5 MHz 的单向原始上限约为 0.9375 MB/s，实际还有半双工、协议和处理开销。15 MHz 板级可靠性、完整浏览器上传/下载、满载 RPC、10 分钟稳定性与最慢环节 70% 的原计划验收尚未完成。以下测试测的是性能监控报告间隔，不是按键到网页呈现的物理延迟，也不是带宽验收。

## Button Performance

- STM32 不再连续发送整组 checkpoint 后才发送实时采样；实时采样和 checkpoint 分片交错，保留 RPC、按键边沿与已编号待重试报告的所有权。
- TX 将 WebConfig 报告复制、清零和 CRC 热点放入 SRAM；接收解析按块推进，保留跨块头、嵌入同步字节、CRC、连接代次、累计确认及队列边界检查。
- SPI 端口的快速复制仅在 WebConfig 高速模式提交后启用，启动/IAP 仍使用原有路径。曾验证到不加这个门控会导致启动 HS_CAPS 超时，该实验版本已被替换。
- 网页的小型实时报告直接按传输顺序解码，保留 RAF 合并渲染；旧 checkpoint/sample 不覆盖更新的按键状态，处理时间戳回绕和断线后的旧回调。

临时 TX 诊断曾测得单个 USB IN 从就绪到完成平均约 105 us，但下一次报告就绪间隔约 21.8 ms；优化后恢复预期 100 Hz 采样。临时能力字段诊断已全部移除，正常能力报告保留字段为零。

灯光预览命令成功后，保持按键监控并用四个在途发送提交 20 次交替的 3984/12000 字节只读 RPC，全部成功并通过加密标签验证。测试不写配置 Flash。原生 HID 不替代真实浏览器端到端验收，最终页面手感待用户确认。

## 保存与配置加载

- 自动保存采用最后一次修改后的 3000 ms 尾沿延迟，每次修改重新计时；移除强制最大等待窗口。
- 保存期间的新修改重新启动尚未提交资源的等待时间；已经开始的事务正常完成。
- Finish Configuration 排队等待当前保存，排空剩余修改并等待设备命令队列完成，再发送退出。保存失败不退出。
- 每次连接从设备全量读取所有配置模块；manifest 仅用于这次读取的一致性检查。无变化的重连也执行全量读取。
- 产品路径不再创建、读取或写入配置快照缓存，并请求删除旧 `xora-config-cache` IndexedDB。旧页面持有连接时删除会等待旧连接关闭，新页面不会使用该缓存。页面内尚未保存的草稿仍属于当前会话状态。
