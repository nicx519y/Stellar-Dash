# XORA 设备故障日志

## 实现范围

新增记录与自动落盘受 Device Logs 顶部的“设备日志记录”开关控制，默认关闭，与“诊断监控采集”独立；权限同步、历史读取及验证边界见[日志与诊断的独立开关](diagnostics-policy.md)。下述记录行为均以开关已开启为前提，独立电池测试除外。

主控、TX、RX 分别保存自己的故障记录。主控和 TX 沿现有加密 WebHID / BoardLink 管理事务读取，RX 沿自己的诊断 HID 读取。云端上传、自动烧录和部署不在范围内。旧 `LOG_*` 文本调用仍为空实现；结构化入口是 `XoraLog_Event` / `XoraLog_GameSample`，`Logger_Flush` 只设置申请标志。

屏幕启动的独立电池测试见[电池测试模式](battery-test-mode.md)。测试使用图片区尾部独立划出的 `0x90770000–0x9077FFFF`（64 KiB），保留原故障区全部 64 KiB 预算；图片读写边界同步收缩。新增 `source=battery`、category=4、INFO=1，TX 故障日志不变。测试专用窗口不放宽原故障日志写入规则。

日志是低优先级功能。仅确认断链或 fatal 事件及其后续恢复证据可进入持久队列；下表的其他异常只参与 RAM 状态与计数，不单独触发 Flash 写入。主动模式切换、已通知的输入暂停、USB 挂起及首次未连接都不能当作确认断链。原串口高频日志开关保持不变。

### 游戏连接事件（2026-10-25）

| 场景 | 检测位置与证据 |
|---|---|
| USB 已挂载后连接丢失、总线复位、挂起 | TX / RX 状态转换与中断通知；首次枚举复位不报断线 |
| TX USB 枚举未完成 | 已取得主机地址后 5 秒仍未挂载；单独供电不启动计时 |
| RF 首次无法连通、RX USB 未就绪 | 已接纳真实输入后持续 5 秒仍未连接；空闲上电、未收到输入不启动计时 |
| USB 报告停止完成 | 有待发数据且挂载、未挂起，完成间隔超过 `max(20 ms, 32 个报告周期)` |
| 上游输入停止 | 明确期待输入后超过 50 ms 没有新输入；TX USB 由主控通过 `INPUT_EXPECTED` 通知主动暂停/恢复 |
| 输出拥塞 | 100 ms 窗口至少丢弃 8 条，同时 USB 完成间隔至少 5 ms；不把正常最新状态合并当拥塞 |
| RF 掉线、无线收发/定时故障 | TX / RX 连接转换及既有 radio fault 入口；不改变频道策略和恢复阈值 |
| RX 输入过期及释放按键 | 记录中立报告请求、实际 USB 完成；不能把排队当成已完成 |
| 板间通信、USB 速率降级 | 主控与 TX 原有故障/兼容恢复判定；保留原始状态码 |
| 采样停止、启动失败、恢复失败、电源保护中断 | 主控现有失败与停机分支；恢复结论限于该端可验证的状态 |

事件 200–204 分别为开始、症状增加、恢复、现场信息、恢复操作，数据 V1 固定 14 个 u32：版本、端内事件编号、USB/RF 模式、原因位图、开始时间、已持续时间、状态、输入数、完成数、丢弃数、输入间隔、完成间隔、速率/协议、原始详情。定义以 [game_link_log.h](../common/game_link_log.h) 为准。故障持续时只合并新增症状，恢复要求持续 200 ms 的有效完成进展；主控使用既有本地恢复确认点。TX RF 的完成数是有效 ACK，TX USB / RX 是 USB 端点完成，都不证明游戏已消费输入。

正常收发只在原有临界区更新计数/通知位，主循环每 5 ms 检查。确认断链采用两类证据：曾连接的 USB/RF 连续 5 秒不再就绪（不含挂起、主动暂停或首次连接超时），或主控已经决定终止输入/耗尽 RF 恢复次数。前者只观察现有状态，不改变协议掉线阈值、重连节奏或参数。原因位图 bit 16 表示“已确认断链”，原有记录长度、版本与原因位保持兼容。

临时错误、状态查询超时、单次恢复失败、速率降级、USB 复位/挂起、拥塞、恢复操作与 `Logger_Flush` 均不能授权落盘。`XoraLog_EventData` 在队列入口拒绝不合格事件，避免普通异常触发记录 CRC/缓存清理；三端的服务入口还检查有效待写证据。丢弃统计只保留在 RAM 元数据中，不作为独立落盘原因。旧版本遗留的普通错误队列在温复位恢复时同样经过资格过滤；已有 Flash 历史不改写。

运行中的输入、RF、USB 以及所有恢复尝试均不为日志创建停机窗口：不得停 ADC/TIM2、重启采样、停止无线、暂停 USB 端点或延迟恢复。移除主控 RF `park()` 中的日志停采样，以及 TX/RX 主循环的自动持久化。即使已经确认断链，只要还在等待接收或重连，证据也继续留 RAM。

持久化只在启动业务前、业务自身已结束的断开入口或已脱离游戏的维护窗口有界执行，最多服务四次；安全窗口和事件资格缺一不可。CPU fatal 只写复位保留 RAM，在下次启动安全窗口提交，异常处理内禁止擦写 Flash。存储失败锁存，不忙循环重试。没有安全窗口时允许延后或丢失日志，不能影响游戏恢复。运行队列与崩溃现场保持原有 CRC、提交顺序、温复位去重与两槽预算。

此次低优先级策略的主机检查覆盖：普通错误/挂起/单独 flush 零写入，确认断链前恢复不落盘，确认阈值与毫秒回绕，未连接设备不误判，安全窗口门禁，fatal/温复位重放，以及运行路径不得调用日志停机入口。三端编译和 ELF 布局检查不代替实机输入、掉线恢复与掉电验收；本次未烧录。

### RX 独立诊断会话

RX Data-Flash 使用 `0x1000–0x5FFF`，保留 `0x0000`，不碰 `0x6000/0x7000` 绑定区及代码 Flash。既有 96 字节记录格式增加来源 4（来源 3 保留给电池测试），每个 128 字节槽最后提交，20 KiB 最多 160 条。未知占用/损坏不能自动格式化。

沿原 RX 32 字节 Feature OUT / EP6 IN 诊断 HID，新增 `RLG1` magic，版本 1、事务号、分片号和 CRC16；INFO 返回 36 字节、READ 返回 96 字节、CLOSE 恢复、CLEAR 必须带 `CLR1` 确认值。与绑定及监视器帧区分，不改变描述符或空口。字段见 [rx_log_protocol.h](../common/rx_log_protocol.h)。读取前暂停无线输入并尝试送中立报告，结束、USB 复位或 5 秒无请求后释放；暂停期间保持中立报告发送，不继续旧游戏状态。Flash 操作在主循环，清空必须检查安全窗口并逐扇区回读。

网页选择 RX 后手动选接收器。RX 日志与绑定共用接收器独占租约，组件通过 `device-transport/rx-log-client.ts` 使用该通道。离开时停止后续请求并尝试 CLOSE；设备拔除、旧固件超时、CRC/分片错误显示不完整，不用主控记录代替 RX。旧固件不会隐式降级读取。

## 格式与隔离

| 项目 | 定义 |
|---|---|
| STM32 | QSPI `0x90560000–0x9056FFFF`，C/Python 的 `FAULT_LOG_STORAGE_*`；配置 bank B 仍在 `0x90580000` |
| TX | **Data-Flash** `0x1000–0x5FFF`；不是 Application 代码 Flash。metadata 在 `0x0000`，绑定区 `0x6000–0x7FFF` |
| 记录 | `common/fault_log.h`：V1 magic、序号、启动编号、uptime、固件 semver、事件、来源、级别、类别、重复次数、14 个现场 word、CRC、最终提交字 |
| 空间 | 96 字节正文占 128 字节槽；4 KiB 扇区循环，仅回收下一个最旧扇区 |
| 提交 | 写正文、回读校验、写最终提交字、再次回读；提交前断电不产生有效记录 |
| 损坏 | 有效记录继续可读；未知格式/损坏已提交记录所在扇区不自动擦除，读失败禁止追加；显式清空另走确认命令 |

按当前布局，主控故障区 64 KiB 可容纳最多 512 条，TX 故障区 20 KiB 可容纳最多 160 条；两者按 4 KiB 扇区循环回收，回收时实际保留条数会暂时下降。电池测试独立区共 64 KiB，扣除 4 KiB 头部后有 480 个记录槽，保留历史且不自动循环覆盖。以上为持久化物理容量，不包含 RAM 待落盘记录，也不是设备当前已有条数；电池测试的记录预算和启动限制另见[测试模式](battery-test-mode.md)。

CRC 覆盖提交字之前的正文。未知格式可能阻止继续写入，状态必须如实返回，不能通过自动格式化恢复。序号达到 `UINT32_MAX` 时停止追加，不回绕为 0。

两端的启动编号、运行时间各自独立，不能据此跨芯片排序。固件号编码为 `major<<16 | minor<<8 | patch`。导出时间属于浏览器，不是事件发生时间。

## RAM、异常与写入窗口

- 每端两个 RAM 事件槽，重复事件合并计数；满时统计丢弃，致命现场使用独立保留 mailbox。丢弃数只作为 RAM 元数据，不独立落盘。日志写入失败在本次启动锁存，不递归记录自身错误或无限重试。
- STM32 异常入口保存原始 `EXC_RETURN`，选择 MSP/PSP，处理浮点扩展帧，校验地址与 stacking fault 后读取寄存器。NMI、HardFault、MemManage、BusFault、UsageFault、`Error_Handler` 和 assert 进入同一最小捕获路径。
- 异常路径不使用堆、锁、格式化或 Flash 操作；保留 RAM 带 magic/CRC，STM32 在重启前清理对应 DCache。下次启动成功提交后才消费，复位发生在提交与消费之间时由不可变现场去重。
- STM32 mailbox 为 `.xora_fault (NOLOAD)`，在 BSS 后、DTCM 栈外；启动代码按符号复制/清零。bootloader 的数据、BSS 和栈在 DTCM。TX `.noinit.xora_fault` 在 `_ebss` 后，独立 IAP 的 load/clear 区不重叠；当前链接不含 `_sbrk`。每次改链接、SDK 或静态 RAM 分配后必须重新运行 ELF 布局检查。
- TX 日志状态、事件槽、保留现场和计时状态预算合计不超过 512 字节，不使用整扇区缓存。ELF 检查还要求保留区上方至少 2 KiB 栈空间；静态空间检查不等于实机栈峰值验证。
- 启动时在传输启动前提交保留现场。运行期不为日志停机，保留业务自身已断开的入口以及 Maintenance/WebConfig 且 USB 未挂载的窗口；主控同时排除升级占用。正常 USB/RF 输入期间不擦写日志。RX 显式诊断会话允许在 USB 挂载状态下停业务并安全访问日志。
- 服务调用在同步主循环、RPC 处理结束后执行，因此与配置、资源、升级、绑定写入串行。QSPI 写入临时移除等待回调，恢复映射并失效日志缓存；映射恢复失败转入 RAM 异常记录/复位，不能继续读失效映射。每次服务最多提交一条，底层擦除/编程等待使用原驱动的有界超时。
- 连续三次异常重启且未稳定运行 30 秒时进入维护限制。TX 拒绝业务角色并返回 `ROLE_LOCKED`，STM32 转入 WebConfig。维护路径再次异常时停止自动复位；持久 TX ISP 状态仍优先，不改变已验收 ISP 流程。

RAM 缓冲和保留现场用于普通复位路径；断电、主控切断 TX 电源或启动前的严重异常仍可能丢失未落盘记录。瞬间断电无法保证记录最后一次拔线；一端的日志也不能证明另一端发生了什么。日志不得延长游戏恢复；运行中没有安全窗口就保持待落盘。已有提交记录与配置、绑定数据相互独立。

## 读取协议

`get_device_logs_list` 保留 `items: string[]` 和 `count`，返回 STM32 最近最多 50 条。新增 `get_device_logs_page`：

```json
{"source":"stm32","category":0,"severity":0,"limit":8}
```

主控 RPC 来源为 `stm32` / `tx`（及独立电池测试 `battery`）；`rx` 只由接收器客户端提供同样的网页分页模型。类别 0=全部、1=异常、2=链路、3=恢复；级别 0=全部、1=信息、2=警告、3=错误、4=致命。响应 V1 包含 `status`、`upper`、`oldest`、`nextBefore`、`more`、`overwritten`、`pending`、`dropped`、`firmware`、`restricted`、`items`。

下一页传回同一来源的 `upper`、`oldest` 和 `before=nextBefore`。上界固定、序号向下推进；保留 RAM 仅在首页读取。循环覆盖使原始 oldest 消失时返回 `overwritten`。RAM 快照不强制落盘，也不与后续页重复合并。

状态区分 `ok`（可能为空）、`unsupported`、`unavailable`、`storage_error`。单个损坏/不可读槽不妨碍返回其余有效记录；整端断线不阻断另一端。读取不能触发日志写入。

TX 使用 `USB_BOARD_CONTROL_FAULT_LOG`，INFO 返回 `fl_info` V1；READ 请求为 upper/before/category/severity/pending-index/offset，96 字节记录分两帧传输，沿用事务号校验并额外核对 offset、长度与 CRC。单字节 `0xFF` 表示没有匹配记录，与超时不同。没有新增 RF 空口协议。

## WebConfig

所有已连接用户可进入“设备日志”。每个来源初始显示“开始读取日志”；点击或刷新后，沿固定快照串行读取全部记录，以游标在快照范围的位置展示进度，完成前不渲染列表。期间锁定来源、筛选、刷新、清空、导出及页头操作；切换页面确认后停止继续翻页，已发出的只读请求自然结束，浏览器关闭/刷新使用原生离开提示。右侧卡片内部滚动，参照 connect-monitor 使用可视区域加六行 overscan 的虚拟列表，并测量展开记录的高度。读取结果按来源缓存，筛选在已读取快照上执行；中途失败保留可读记录并标记不完整。

导出所有已读取来源的完整快照，不受当前显示筛选影响，不另发读取请求；文件仅对已包含来源声明读取完整性。连接事件另外按来源/启动/模式/编号生成摘要，不跨端拼接时间线。部分失败、损坏、覆盖或丢弃设置 `complete=false`。待落盘标记始终说明断电丢失风险。旧固件不支持新命令时显示兼容提示。

`clear_device_logs` 属于 `config.write`，仅接受单一 `source` 和布尔 `confirm=true`。网页先显示不可撤销确认，再进入配置事务边界暂停监测/预览，等待设备明确成功应答；清空期间禁止站内导航。固件只擦除该来源专用分区，每个 4 KiB 扇区擦除后完整回读，全部成功才丢弃待落盘记录和计数；异常维护状态/崩溃次数不随清空解除。TX 使用现有日志管理事务的独立 4 字节 `CLR1` 请求，旧 TX 会拒绝，清空等待上限独立扩至 5 秒，读取事务仍为原超时。主控恢复 QSPI 映射并处理缓存；电池区检查新旧图片边界、活动测试拒绝，数据区全部校验后才擦除头部，允许后续新一轮测试。中断或失败可能留下部分历史，返回失败且不自动重试、续擦或宣称成功；重新读取检查设备状态。

Mock：`/view-logs/?mockLogs=connection|normal|empty|unsupported|tx-unavailable|corrupt|overflow`，只在 Mock 变体使用。

实机验收须另行明确授权：注入异常后复位读取、断电读回已提交记录、TX 单端失联、损坏/覆盖提示、正常切换不误报、三次崩溃限制、维护再次崩溃停机、栈峰值、启动握手与输入延迟。主机模型和编译通过不能替代这些结果，当前不运行暂停中的 RF 回归或设备采样。

回退上一版本应用固件与网页即可停止功能；不清空日志区，不迁移配置或绑定，不修改 bootloader/IAP 镜像、冻结烧录脚本或保护状态。
